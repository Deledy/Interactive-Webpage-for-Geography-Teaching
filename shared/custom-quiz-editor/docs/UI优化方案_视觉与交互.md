## 1. 问题诊断：三条痛点 → 具体症状 → 对应改法

| 用户反馈 | 诊断到的具体症状 | 本轮改法 | 章节 |
| --- | --- | --- | --- |
| 视觉效果粗糙 | ① 控件只有 34px 高、字号集中在 12–14px，层级扁平；② 编辑区与预览区挤在一起，缺呼吸感；③ 卡片/输入框描边与底色接近，浮不起来；④ 顶栏 7 个按钮同权重平铺 | 重建字号/间距/圆角/阴影标尺；拉开面板与卡片留白；卡片加描边+阴影双层区隔；顶栏拆主次分组 | §2 |
| 用户引导缺失 | ① 首次打开只有一个空态提示，没有「先做什么」；② 结构已载入但内容为空时，编辑区只说「0 条」，没有下一步入口；③ 字段没有示例文案，不知道填什么 | 新增「上手步骤」引导条（四步 + 情境化按钮）；空态分步引导；空分组就地引导卡；全部字段补占位提示 | §4 |
| 操作路径不清晰 | ① 「校验/导入结构/导入数据/载入同级/导出/复制/保存」7 个动作平铺，看不出先做哪个；② 校验失败只报数量，不知道去哪改；③ 点击无加载态 | 顶栏分「次要操作（校验 + 更多菜单）」与「主路径（导出 → 保存）」；校验问题可定位并高亮到字段；保存加 loading | §3 |

## 2. 视觉规范调整明细

### 2.1 色彩系统

**① 强调色更换：从通用蓝换成中性靛紫（`#4c6ef5` → `#5b5bd6`）**

上一版使用了 SaaS 品类默认的蓝，缺乏设计判断。本组件是**无业务属性**的通用工具，因此选一个可解释的中性强调色：靛紫在灰阶中性体系里辨识度足够、不指向任何行业语义，也不会与项目既有课程配色（金/青/深空蓝）混淆。

| 令牌 | 浅色（旧 → 新） | 深色（旧 → 新） |
| --- | --- | --- |
| `--ce-accent` | `#4c6ef5` → **`#5b5bd6`** | `#748ffc` → **`#9b9bf5`** |
| `--ce-accent-hover` | `#4263eb` → **`#4f4fc7`** | `#8ea2ff` → **`#adadf9`** |
| `--ce-accent-active` | 新增 | **`#4646b5` / `#bcbcfa`** |
| `--ce-accent-soft` | `rgba(76,110,245,.10)` → **`rgba(91,91,214,.09)`** | `rgba(116,143,252,.14)` → **`rgba(155,155,245,.15)`** |

**② 背景与表面分层**：由「背景 = 面板色」改为**四级表面**，让容器与内容自然分层，是"整洁感"的主要来源。

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--ce-bg` | `#f6f7f9` → **`#f4f5f8`** | `#16181d` → **`#131418`** | 应用底色 |
| `--ce-surface` | `#ffffff` | `#1e2127` → **`#1b1d23`** | 卡片 / 顶栏底 |
| `--ce-surface-2` | `#f1f3f5` → **`#f1f2f6`** | `#24272e` → **`#212329`** | 导航栏 / 引用块 / 答案块 |
| `--ce-surface-3` | `#e9ecef` → **`#e7e9ef`** | `#2b2f36` → **`#2a2d34`** | 输入底 / 标签 / 表头 |
| `--ce-surface-sunken` | 新增 **`#eef0f4`** | **`#17191e`** | 下沉容器 |

**③ 状态色对比度修正（无障碍缺陷）**

旧版 toast 与计数徽标用 `color: #fff` 压在状态实底上。深色主题的状态色是亮色（如 `#4ade80`），白字对比度不足 —— 属实测缺陷。新增 `--ce-on-solid` 令牌按主题取反：

| 令牌 | 浅色 | 深色 | 说明 |
| --- | --- | --- | --- |
| `--ce-on-solid` | **`#ffffff`** | **`#0f1116`** | 状态实底（toast / 徽标）上的文字 |
| `--ce-success` | `#2f9e44` → **`#157f4a`** | `#51cf66` → **`#4ade80`** | 通过 |
| `--ce-warning` | `#a06800` 微调 → **`#a15c00`** | `#ffd43b` → **`#fbbf24`** | 待完善 |
| `--ce-danger` | `#e03131` → **`#d92d20`** | `#ff6b6b` → **`#f87171`** | 错误 / 删除 |

**④ 硬编码颜色归零**：组件样式内的 `color / background / border-color` 已 100% 走 `--ce-*` 令牌（校验结果：`hardcoded color decls: 0`），换肤与主题扩展不再需要改规则。

### 2.2 字体层级

字号由「6 级、集中在中段」改为「7 级、两端拉开」，让标题与正文产生明确落差。

| 令牌 | 旧值 | 新值 | 典型用途 |
| --- | --- | --- | --- |
| `--ce-fs-2xs` | — | **11px** | 标签、导航计数、引导步骤号 |
| `--ce-fs-xs` | 12px | **12px** | 面板标题、字段标签、按钮(sm) |
| `--ce-fs-sm` | 13px | **13px** | 控件文字、卡片正文、菜单项 |
| `--ce-fs-md` | 14px | **14px** | 根字号、预览正文 |
| `--ce-fs-lg` | 16px | **15px** | 空态标题、预览小标题 |
| `--ce-fs-xl` | 18px | **18px** | 顶栏标题、预览分组标题、对话框标题 |
| `--ce-fs-2xl` | — | **22px** | 编辑区分组大标题 |

配套强化：
- 标题字重统一提到 **650**（旧 600），正文 400，控件 550 —— 用字重而非线框建立层级；
- 行高拆为 `--ce-lh-tight:1.3`（标题）/ `--ce-lh-base:1.6`（正文）；
- 顶栏标题与大标题加 `letter-spacing:-.01em`，中文大字号更紧凑；
- **移除面板标题的 `text-transform:uppercase`**（对中文无效且是拉丁中心主义写法），改用轻微字距 `--ce-tracking:.06em`。

### 2.3 间距与留白

| 令牌 | 旧值 | 新值 | 说明 |
| --- | --- | --- | --- |
| `--ce-panel-pad` | 20px | **24px** | 三大面板内边距（紧凑 16 / <768px 16） |
| `--ce-card-pad` | 16px | **20px** | 卡片内边距 |
| `--ce-row-gap` | 8px | **14px** | 字段间距 |
| 卡片间距 | 16px | **20px** | 卡片之间的呼吸 |
| `--ce-nav-w` | 240px | **264px** | 导航更宽，标题不易截断 |

同时引入卡片内**分节留白**：`ce-subhead` 以「上间距 24px + 分隔线 + 下间距 12px」把长表单切成「分组设置 / 条目」两个可扫读的区块，解决"一屏全是输入框"的问题。

### 2.4 卡片与按钮

| 项 | 旧 | 新 |
| --- | --- | --- |
| 圆角 | sm 6 / md 8 / lg 12 | sm 6 / **md 9 / lg 14** |
| 阴影 | 2 级 | **3 级（xs / sm / md）**：卡片 xs、悬浮 sm、浮层 md |
| 卡片 | 单层淡描边 | **描边 + shadow-xs 双层区隔**；条目卡 hover 提升到 shadow-sm 且描边加深 |
| 按钮 | 34px / primary 有底 | **38px（sm 30px）**；primary 增加 `box-shadow` 与 hover/active 三态；新增 `is-loading` 态 |
| 命中区 | 跟随控件高度 | 新增 `--ce-hit:40px`（图标按钮 40×40，导航项 `min-height:48px`）；`@media (pointer:coarse)` 全量放大到 44/38/46 |
| 面板切换 | 三个独立按钮 | 合并为 **`ce-segment` 分段控件**，当前态用"白底 + 阴影 + 加粗"表达 |

### 2.5 视觉对照速查（旧 → 新）

| 位置 | 变化 |
| --- | --- |
| 顶栏 | 新增 34×34 强调色 Logo 块 + 标题/副标题双行；动作区拆为「次要组 ─ 分隔线 ─ 主路径组」 |
| 工具条 | 由「状态 + 3 个控件」变为「状态（含可点击定位）· 引导回显 · 分段切换 · 主题」 |
| 新增引导条 | 强调弱底横条，四步流程 + 当前步高亮 + 情境化主按钮 + 关闭 |
| 导航项 | 金色/灰色圆点序号 → 中性方形序号片；标题加粗到 550；计数移到第二行 |
| 编辑区 | 新增分组大标题（22px）、两个分节标题、字段标签+占位提示 |
| 条目卡 | 序号片 + 类型标签 + 右上角操作组（图标化上移/下移、文字复制/删除） |
| 预览区 | 分组标题 18px；条目卡加阴影；答案块标题用强调色而非金色 |

## 3. 交互逻辑改进点

### 3.1 顶栏：主次操作分层 + 「更多」菜单

**旧**：7 个按钮平铺（校验 / 导入结构 / 导入数据 / 载入同级 / 导出 / 复制 / 保存），除"保存"外全是幽灵样式，主次不可辨。

**新**：

```
[ 校验 (3) ]  [ 更多 ▾ ]   │   [ 导出数据文件 ]  [ 保存到同级文件 ]
   └ 次要操作组（低频）        └ 主路径组（完成动作）
        └ 导入结构文件 / 导入数据 / 载入同级文件 / 复制
```

- 主路径按钮在最右，`保存`为唯一实底 primary；
- 高频的「校验」留在外层并带**问题计数徽标**（红色计数，0 时自动隐藏）；
- 低频动作收进「更多 ▾」下拉菜单，`aria-haspopup` / `aria-expanded` / 点击项后自动收起；
- 点击空白处或按 `Esc` 关闭菜单；`mousedown` 在菜单外即收起，避免"要再点一次才关"的常见顿挫。

### 3.2 校验：从「报数量」升级为「可定位、可高亮」

**旧**：状态条一行文字「校验发现 N 处待完善」+ 前两条摘要，用户不知道去哪改。

**新**：

1. `collectIssues()` 返回**结构化问题**：`{ label, message, base, paths[] }`，`base` 指向条目、`paths` 指向具体字段；
2. 状态条显示「校验发现 N 处待完善：<第一条具体问题>」+ 内联 **[定位到第一个问题]** 链接；
3. 点击定位：`scrollIntoView({behavior:'smooth', block:'center'})` + 聚焦该字段；
4. 同时**把问题标回编辑区**：问题条目卡加 `is-invalid`（红描边），具体字段加 `is-invalid` + `aria-invalid="true"`（红描边 + 危险弱底）；
5. 顶栏校验按钮徽标同步计数；校验通过时状态条转绿色并提示"可以保存或导出"。

### 3.3 状态反馈：补齐 hover / active / disabled / loading / 成功 / 错误

| 状态 | 表现 |
| --- | --- |
| hover | 颜色 + 描边 + 阴影过渡（120ms，`--ce-ease`） |
| active | `translateY(1px)`，primary 切到 `--ce-accent-active` |
| focus-visible | 3px `--ce-ring` 焦点环 + 强调描边（全组件覆盖） |
| disabled | `opacity:.5` + `cursor:not-allowed`，禁用位移 |
| **loading** | 新增 `is-loading`：文字透明 + 居中旋转环；「保存到同级文件」在写盘期间进入该态，`aria-busy="true"` |
| 成功 | 绿色 toast（`已保存到所选文件` / `校验通过，可以保存或导出`） |
| 错误 | 红色 toast（`导入失败：<原因>` / `解析失败：<原因>`），toast 增加位移动画进入 |
| 提示 | 黄色 toast（`校验发现 N 处待完善，可点「定位到第一个问题」跳转`） |
| toast 时长 | 1.8s → **2.6s**，长句可读完 |

### 3.4 键盘与无障碍

| 项 | 实现 |
| --- | --- |
| 对话框焦点陷阱 | 新增：`Tab` / `Shift+Tab` 在对话框内循环，**且已修正作用域**（此前 `querySelectorAll` 的多选择器写法会把选择器泄漏到整个文档） |
| 对话框默认焦点 | 落在「取消」（破坏性操作的安全性默认） |
| `Esc` | 优先关菜单，其次关对话框 |
| 语义 | 状态条 `role="status" aria-live="polite"`；对话框 `role="dialog" aria-modal="true"`；装饰图标 `aria-hidden="true"`；纯图标按钮补 `aria-label` + `title` |
| 状态类 | 统一 `is-*`（`is-active` / `is-invalid` / `is-loading` / `is-dragover` / `is-done` / `is-current`） |
| 动效降级 | `prefers-reduced-motion` 下全部过渡/动画归零 |

### 3.5 输入时的更新策略（避免打断输入）

**旧**：每次按键都 `renderNav + renderPreview + renderValidation`，虽未重建编辑区，但校验会在半句话时立刻报错。

**新**：拆分为两条路径

- `renderAll()`：结构变化时全量渲染，并把**校验提前到 `renderEditor()` 之后**统一计算（`renderEditor` 会惰性创建分组对象，此前会污染"尚无任何条目"的判断 —— 本次一并修正）；
- `renderOnInput()`：仅更新导航计数、预览、校验、引导，**不重建编辑区**，输入焦点不丢。

## 4. 用户引导的具体实现方式

引导分四层，覆盖"从没打开过 → 用户知道该做什么"的完整落差。

### 4.1 「上手步骤」引导条（核心机制）

位置：顶栏与工具条之间，`#guide`。仅在**未完成且未被关闭**时显示。

四步与完成判定（全部自动推断，无需用户打勾）：

| 步骤 | 文案 | 完成条件 |
| --- | --- | --- |
| 1 | 载入结构 | `manifest` 已加载 |
| 2 | 选择分组 | 已选中某个分组 |
| 3 | 填写内容 | 条目总数 > 0 |
| 4 | 校验并导出 | 有内容且校验 0 问题 |

呈现细节：
- 步骤号：未开始 = 灰底数字；当前 = **强调实底数字 + 白底胶囊 + 加粗**；已完成 = 绿色 `✓`；
- 步骤间用 `›` 连接，`title` 悬浮显示该步说明；
- 右侧放**情境化主按钮**——只出现"当下这一步该做的事"：

| 当前未完成步骤 | 按钮 | 行为 |
| --- | --- | --- |
| 1 载入结构 | 导入结构文件 | 打开文件选择器 |
| 2 选择分组 | 选择第一个分组 | 自动选中首个分组 |
| 3 填写内容 | 新增<题型> | 在当前分组新建一条（辅助区会自动补一个分区） |
| 4 校验并导出 | 开始校验 | 触发校验并定位问题 |

- 四步全部完成 → 引导条**自动收起**，不再占用视觉空间；
- 用户点关闭 → 记入 `localStorage`，下次不再打扰；
- 收起后工具条出现 `?` 图标按钮可随时调回（**修正**：此前完成后点该按钮无反应，现引入 `guideForced`，显式调回时即使已完成也展示）；
- 引导可用 `layout.guide: false` 整体关闭，文案全部走 `labels.guide.*`。

### 4.2 空态分步引导（无结构时）

编辑区空态由"一句提示"升级为：

```
[ 图标 ]
尚未载入结构清单
结构清单决定左侧有哪些分组。载入后即可逐组编辑内容，右侧实时预览效果。
1  载入结构   导入结构文件，确定有哪些分组
2  选择分组   在左侧点选一个分组
3  填写内容   新增条目并填写字段
4  校验并导出 通过校验后保存或导出
[ 导入结构文件 ]  [ 载入同级文件 ]
也可以把结构文件直接拖到左侧「分组」面板。
```

要点：**主按钮在前**（导入结构文件 = primary），次按钮（载入同级文件）用常态按钮，与 §3.1 的主次规则一致；末尾补充拖拽这一隐藏能力，降低"找不到入口"的概率。

### 4.3 空分组就地引导卡

结构已载入但某分组还没有内容时，在「条目」分节下显示虚线引导卡：

> **该分组还没有内容**
> 从下方按钮新增第一条内容，右侧会同步预览效果。

紧随其后的是新增按钮行，且**第一个按钮为 primary**（引导视觉落点），同时保留全部题型入口。

### 4.4 字段占位指引

为易混淆字段补齐 `placeholders.*`（纯示例语气，不含业务词）：

| 字段 | 占位提示 |
| --- | --- |
| 正文 | 填写本条目要展示的正文内容 |
| 背景 | 可选，为条目补充背景材料 |
| 来源 | 可选，标注内容出处 |
| 说明 | 可选，说明判断依据或补充解释 |
| 参考内容 | 填写参考内容，支持 Markdown |
| 补充说明 / 评价要点 / 问题 | 每行一条（一条/一点），将渲染为列表 |
| 分组标题 | 可选，用于覆盖结构清单中的分组名 |

### 4.5 引导与校验的衔接

引导第 4 步与 §3.2 的校验定位打通：点「开始校验」若存在问题，toast 直接告诉用户「可点『定位到第一个问题』跳转」，形成"发现问题 → 跳到问题 → 修完 → 引导步进"的闭环。

## 5. 兼容性与回归

| 项 | 结论 |
| --- | --- |
| 数据契约 | 零改动。`modules` / `postLesson` / `questions` 结构与导出文件名不变，现有分发包无需改动 |
| 配置兼容 | `layout.guide` 与新增的 `labels.guide.*` / `labels.placeholders.*` / `labels.sectionTitles.*` / `labels.hintCard.*` 均为**可选**，缺失走默认值；旧配置对象继续可用 |
