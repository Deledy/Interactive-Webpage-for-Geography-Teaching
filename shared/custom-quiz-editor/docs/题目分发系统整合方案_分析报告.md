## 0. 摘要

当前系统的**题目数据已外置**，但**编辑器仍在仓库内、未进入分发包**，导致教师需要"另找入口"，与"同文件夹点击进入"的目标不匹配。本报告梳理现状、给出 4 种可落地方案，推荐 **方案 A（最小改动、全兼容）打底 + 方案 B（File System Access API 就近写回）增强**，二者共用同一份代码、双通道回退，可在**不影响原有分发流程**的前提下显著改善教师体验。

> **落地状态（2026-10-10）**：推荐方案（A + B）与 P3 健壮性改造**均已实施**，详见 [§7 实施记录](#7-实施记录)。

---

## 1. 需求背景

**目标**：将「题目自定义页面」与「主页面」放在**同一文件夹**，教师拿到分发包后，双击主页面即可**通过点击进入**配置页完成题目配置，无需跳转到独立配置入口。

**关键事实**：本项目为**纯静态、无后端**，存在两种分发形态，行为差异显著：

| 分发形态 | 产物 | 打开方式 | 能力边界 |
| --- | --- | --- | --- |
| 离线 zip（当前主用） | `dist/` → `<课名>.zip`（见 [build.mjs](../../../scripts/build.mjs)） | 双击 `index.html`（`file://`） | 不能 `fetch` 外部 JSON；可加载经典 `<script src>`；可下载文件 |
| 在线托管 | `dist-book/`（见 [deploy.mjs](../../../scripts/deploy.mjs)） | `http(s)://` | `fetch` 可用；若引入服务端才可能有"后端接口" |

> 因此下文"后端接口适配"在本项目中**默认不存在**，将替换为"本地文件系统读写"；仅方案 D 涉及真实 HTTP 接口。

## 2. 现状梳理与可优化点

### 2.1 现状链路

```
仓库源码 ──build.mjs/vite──▶ dist/（单文件 index.html + 外置 custom-quiz.js + assets）──▶ 打包 zip ──▶ 教师解压
                                                                                                │
编辑器在 shared/custom-quiz-editor/index.html（仓库内）◀── 教师需"另找入口" ── 导出 custom-quiz.js ──▶ 手动覆盖 dist 内文件
```

| # | 环节 | 实施前现状 | 问题 | 现状 |
| --- | --- | --- | --- | --- |
| 1 | 分发物内容 | `public/` 只有数据文件，编辑器在 `shared/` | **编辑器不进分发包 → 教师拿不到（核心断层）** | ✅ 已修复（构建复制） |
| 2 | 主页面入口 | M10 区块只有"重做练习"按钮 | 无"教师配置题目"入口 | ✅ 已修复 |

## 3. 可行方案

> 通用落位约定：编辑器产物命名 `custom-quiz-editor.html`（**ASCII 名**，规避中文名在 `file://` 相对链接下的编码问题），与 `index.html`、`custom-quiz.js` 同级。

### 方案 A：同目录静态页 + 下载写回（最小改动，全兼容）

**页面结构**
```
dist/
├─ index.html              # 主页面（含「教师：配置题目」入口）
├─ custom-quiz-editor.html # 编辑器（单文件，自带样式脚本）
├─ custom-quiz.js          # 题目数据（编辑器产出）
└─ custom-quiz-demo.svg
```

**前端交互**
1. 主页面 M10 头部加 `<a href="./custom-quiz-editor.html" target="_blank">教师：配置题目</a>`（`file://` 与 `http` 均可用）；
2. 编辑器打开时用同一套"经典脚本注入"技巧自动预填：注入 `<script src="./custom-quiz.js">` → 读 `window.__CUSTOM_QUIZ__`；
3. 改完点「导出」→ `Blob` 下载 `custom-quiz.js` → 教师覆盖同目录文件 → 刷新主页面即生效。

**后端接口适配**
无服务端。以浏览器本地能力替代：`Blob` + `a[download]`（Chrome/Edge/Firefox 在 `file://` 下均可下载）。

**权限校验规则**
纯本地、无真实鉴权。可做**弱门控**（防误触，非安全）：入口用 `#teacher` 哈希 / 长按隐藏触发，或在编辑器首屏加"确认进入"。**明确不做密码**——前端密码可被查看源码绕过，属伪安全。

---

### 方案 B：同目录静态页 + File System Access API 就近写回（体验最佳，Chromium 桌面）

**页面结构**：同 A。

**前端交互**
1. 同 A 的入口与自动预填；
2. 「保存到本文件」→ `showSaveFilePicker({ suggestedName: 'custom-quiz.js' })`（或 `showDirectoryPicker()` 后写入）→ **直接覆盖同目录数据文件**；
3. 能力检测失败 → **自动回退到方案 A 的下载模式**（同一份代码、双通道）。

**后端接口适配**
无服务端。以 `FileSystemFileHandle.createWritable()` 替代"写接口"，语义等价于 `PUT ./custom-quiz.js`。

**权限校验规则**
写权限来自**浏览器对文件句柄的显式授权**（必须用户手势触发、用户亲自在系统弹窗中选择目标文件/目录），等价"教师对本机文件的授权"；首次写入需一次确认，之后可复用句柄。

> **风险提示**：`file://`（origin 为 `null`）下 `showSaveFilePicker` 的可用性**需实测**（安全上下文判定差异），因此必须保留方案 A 回退。

---

### 方案 C：主页面内置"编辑模式"（无独立页，运行时编辑）

**页面结构**：仅 `index.html`，不新增独立页。

**前端交互**：主页面通过 `#teacher` 或隐藏入口切到"编辑模式"，M10 区块内就地增删题；数据存 `localStorage` 并导出 `custom-quiz.js`。

**接口 / 权限**：同 A（本地）。但 `localStorage` 在 `file://` 下**并非所有浏览器/策略都可用**，故只能作草稿，**不能作为分发数据的真源**。

**适用性**：改动最小，但"编辑态"与"学生态"耦合在同一页面，增加学生端体积与干扰 → 仅作备选。

---

### 方案 D（可选扩展）：在线托管形态下的"配置服务"

仅当走 `dist-book/` 在线托管、需要多教师协同 / 统一管理时考虑：

- **接口**：`GET /api/lessons/{lesson}/quiz`（取配置）、`PUT`（写入并版本化）、`GET .../revisions`（历史版本）；
- **权限**：服务端会话 / Token 鉴权 + 按课 / 按校角色（只读 / 可编辑）；数据落库或对象存储；
- 主页面改为 `fetch` 拉取（保留 `custom-quiz.js` 作为离线兜底）。

与当前"无后端"架构差异大，**不建议作为第一步**。

## 4. 方案对比

| 维度 | 现状（优化前） | 方案 A | 方案 B | 方案 C | 方案 D（在线后端） |
| --- | --- | --- | --- | --- | --- |
| 开发成本 | — | **低**（入口 + 构建复制 + 自动预填） | 中（+ FS API 与回退） | 低-中（主页面双模式） | 高（服务端 + 鉴权 + 数据层） |
| 教师体验 | 差（另找入口、手动搬文件） | 好（同目录、点进即用，仍需覆盖一步） | **最佳**（点进 → 直接保存） | 中（就地编辑，入口更隐） | 好（多人协同、统一管理） |
| 维护复杂度 | 低（但有断层） | **低**（编辑器单一真源，构建复制） | 低（多一条回退分支） | 中（学生态/编辑态耦合） | 高（后端运维） |
| 兼容性 | — | **最好**（`file://` / `http` 均可用） | 受限于 Chromium 桌面，需回退 | 受 `localStorage` 可用性限制 | 依赖联网与服务 |
| 对原分发流程影响 | — | **无**（纯增量） | 无 | 中（主页面改变） | 大（数据源改变） |
| 数据安全 | 本地 | 本地 | 本地（用户授权） | 本地 + 浏览器存储 | 服务端鉴权（最规范） |

**结论**：以 **A 打底 + B 增强（同一代码双通道）** 为最优；C 仅备选；D 另行评估。

### 5.4 必须 / 建议 / 可选 / 不建议

## 6. 结论

采用「**方案 A 打底 + 方案 B 增强**」：把编辑器做成同目录静态页并由构建脚本复制进各课 `dist/`，主页面加入口，编辑器自动预填并支持就近写回（含下载回退）。该路径**对原有分发流程零侵入**、兼容性最好、维护成本最低，同时把教师操作路径缩短为"点进 → 改 → 保存"。
