## 1. 目标与范围

### 1.1 目标
在课内新增一个可由**教师按学情自行设题**的练习模块，满足：

- 高中题型：**选择题**（单选 / 多选）、**综合题**；
- **显示答案与解析**（综合题含参考答案、解析、评分标准）；
- 支持 **表格、图片** 等富文本内容；
- 内容**外置**：分发后教师替换数据文件即可更新，**无需重新构建**。

### 1.2 范围内
- 课内 M10 区块的渲染与交互；
- 外置数据文件格式与加载机制；
- 教师可视化编辑器（跨课复用）；
- 与现有构建/分发链路的集成。

### 1.3 范围外
- 学生作答数据的收集、统计与上传（本项目为纯静态、无后端）；
- 在线协同编辑与账号体系。

## 2. 设计要点（约束驱动）

| 约束 | 说明 | 对应决策 |
| --- | --- | --- |
| 分发形态 | 单文件 `index.html`（JS/CSS 内联）+ 大资源外置，`file://` 双击可用 | 数据必须外置且可在 `file://` 下加载 |
| `file://` 限制 | `fetch`/`XMLHttpRequest` 被 CORS 拦截；ES module 亦受限 | 用**经典 `<script src>`** 注入，数据挂全局变量 |
| 图片路径 | 构建后图片文件名带 hash、路径不可预知 | 数据内图片**相对路径**仅用于 `public/` 稳定文件；教师插图推荐 **base64 内联** |
| 技术偏好 | 项目约定「优先原生、少依赖」 | Markdown 子集**自研渲染**，不引第三方库 |

## 5. 数据模型

数据文件为 `window.__CUSTOM_QUIZ__` 全局对象，TypeScript 定义如下（与实际实现一致）：

```ts
interface CqData {
  version?: number      // 数据版本，便于后续演进
  updatedAt?: string    // 最后更新时间（ISO 字符串，编辑器导出时写入）
  lesson?: string       // 课程标识
  title?: string
  subtitle?: string     // 顶部引导语（支持行内 Markdown）
  sections?: CqSection[]
}

interface CqSection {
  id?: string
  title?: string        // 如「一、选择题」
  questions?: CqQuestion[]
}

type CqQuestion = CqChoice | CqEssay

interface CqChoice {
  type: 'choice'
  mode?: 'single' | 'multiple'   // 默认 single
  source?: string                // 题源标注，可空
  material?: string              // 材料（富文本）
  stem: string                   // 题干
  options: { key: string; text: string }[]
  answer: string | string[]      // 单选 'A'；多选 ['A','C']
  analysis?: string              // 解析（富文本）
  knowledge?: { title?: string; items?: string[] }
}

interface CqEssay {
  type: 'essay'
  source?: string
  material?: string
  stems?: string | string[]      // 设问，可多条
  referenceAnswer?: string       // 参考答案
  analysis?: string
  criteria?: string[]            // 评分标准
}
```

**最小示例：**

```js
window.__CUSTOM_QUIZ__ = {
  version: 1,
  lesson: 'geo01-earth-universe',
  title: '自定义练习',
  subtitle: '教师可按学情增删题目。',
  sections: [
    { id: 'p1', title: '一、选择题', questions: [
      { type: 'choice', mode: 'single', material: '材料……', stem: '题干……',
        options: [{ key: 'A', text: '甲' }, { key: 'B', text: '乙' }],
        answer: 'A', analysis: '解析……',
        knowledge: { title: '归纳', items: ['要点一'] } }
    ] },
    { id: 'p2', title: '二、综合题', questions: [
      { type: 'essay', material: '材料……', stems: ['（1）……', '（2）……'],
        referenceAnswer: '……', analysis: '……', criteria: ['① ……'] }
    ] }
  ]
};
```

## 6. 运行时模块设计（customQuiz.ts）

### 6.1 数据加载
```ts
// 收口点：先查全局；否则动态注入经典脚本
const s = document.createElement('script')
s.src = './custom-quiz.js'      // 相对 index.html
s.onload  = () => resolve(window.__CUSTOM_QUIZ__ ?? null)
s.onerror = () => resolve(null) // 文件缺失 → 空态
```
- **为什么不用 `fetch`**：`file://` 下会被 CORS 拦截；经典脚本不受此限。
- **路径**：`./custom-quiz.js` 在开发（Vite 由 `public/` 提供）与构建产物（`dist` 根）下均成立。

### 6.2 容错与空态（P3）
- 文件缺失 / 加载失败 → 渲染「本节课暂未配置自定义练习」空态；
- **结构校验**（`validateQuizData`）：逐题校验——选择题需题干 + ≥2 个选项 + 有效答案（答案键须落在选项内）；综合题需设问或参考答案；非法题目被丢弃并在控制台输出提示；
- 数据 `version` 高于 `DATA_VERSION` → 仅提示，不阻断；
- 无任何有效题目或数据损坏 → 渲染「数据格式有误，已忽略」空态（附前 5 条问题），**不白屏**；
- 渲染过程异常 → `try/catch` 回退空态；
- **不影响页面其它模块**。

### 6.3 Markdown 子集渲染（自研）
| 语法 | 输出 |
| --- | --- |
| `**加粗**` / `*斜体*` | `<strong>` / `<em>` |
| `` `代码` `` | `<code>` |
| `![说明](路径)` | `<img>` |
| `[文字](链接)` | `<a target="_blank">` |
| GFM 表格 | `<table class="cq-table">` |
| `- ` / `1. ` 列表 | `<ul>` / `<ol>` |
| 段落、行内换行 | `<p>` + `<br>` |

实现要点：先 HTML 转义再转换，避免注入；块级按「表格 → 列表 → 段落」逐行扫描。

### 6.4 交互与状态机
- **单选题**：点选即判定 → 显示判定条 + 解析 + 知识归纳，并标注正确 / 错误项；
- **多选题**：勾选后点「提交答案」才判定（未选时按钮禁用）；
- **综合题**：初始只给材料与设问，点「查看参考答案」展开参考答案 / 解析 / 评分标准；
- **重置**：M10 头部「重做本页练习」清空全部作答状态。

## 8. 可视化编辑器设计（shared/custom-quiz-editor/index.html）

### 8.1 形态
离线单文件 HTML（内联样式与脚本），双击即用、无依赖、无需构建。

### 8.2 功能
- 分节 / 题目的增删、复制、上下移动；
- 题型切换（单选 / 多选 / 综合题），选项增删并自动重排 A/B/C…；
- 答案选择（单选 radio / 多选 checkbox）；
- **插入图片**：选本地图片 → 自动转 **base64 内联** 插入光标处（离线最稳）；
- **插入表格**：按行列数生成 Markdown 表格模板；
- 右侧**实时预览**（与运行时同一套 Markdown 子集渲染）；
- **导出 `custom-quiz.js`**（下载 / 复制）、**导入**已有文件；
- **自动预填 / 载入同目录文件**：打开时读取同级 `custom-quiz.js`（本机已有草稿则保留草稿，不覆盖，并提示可手动「载入同目录文件」）；
- **保存到本文件**：`showSaveFilePicker` 就近覆盖同级 `custom-quiz.js`，不支持或被取消时回退为下载；
- **校验并预览**：编辑区顶部**实时**显示结构校验结果（题干 / 选项 / 答案 / 设问缺失等），导出时自动写入 `updatedAt`；
- 草稿存本机 `localStorage`（失败时静默降级为内存态，不阻塞使用）。

### 8.3 兼容性说明
- `localStorage` 在 `file://` 下并非所有浏览器/策略都可用 → 已 `try/catch` 降级；**导出文件才是唯一真源**；
- 复制功能优先用 `navigator.clipboard`，失败回退 `execCommand`。

## 9. 构建与分发集成

- `vite.config.ts` 既有约定：`public/` 原样复制到 `dist/`；JS/CSS 内联为单文件。
- 因此 `public/custom-quiz.js`、`public/custom-quiz-demo.svg` 会出现在 `dist/` **根目录**，与 `index.html` 同级。
- **编辑器随分发包落位**：`scripts/build.mjs` 在每课 `vite build` 后，把 `shared/custom-quiz-editor/index.html` 复制为 `dist/custom-quiz-editor.html`（ASCII 名），再由 `packDist` 一并打入 zip。单一真源在 `shared/`，**不提交各课副本**。
- **开发期入口**：`vite.config.ts` 注册 dev 中间件，`npm run dev` 下访问 `/custom-quiz-editor.html` 即由 shared 编辑器响应，主页面入口在开发期同样可点（不产生副本）。
- 构建后 `dist/` 结构：

  ```
  dist/
  ├─ index.html              # 主页面（含「教师：配置题目」入口）
  ├─ custom-quiz-editor.html # 编辑器（由 shared 复制）
  ├─ custom-quiz.js          # 题目数据（编辑器产出）
  └─ custom-quiz-demo.svg
  ```
- 命令：
  ```
  npm run dev                                            # 单课开发
  npm run typecheck                                      # 全库类型检查
  npm run build:lesson   -- --lesson=geo01-earth-universe  # 产出 dist/ 并打包 zip
  npm run check                                          # 结构校验
  npm run test                                           # 功能测试
  ```

## 10. 教师使用流程

1. 双击分发包中的 `index.html`，点 M10 头部「教师：配置题目」（打开同目录 `custom-quiz-editor.html`）；
2. 编辑器**自动预填**同目录 `custom-quiz.js` 的现有题目；增删 / 编辑题目（选择题、综合题），按需插入图片与表格，右侧核对预览；
3. 点「保存到本文件」就近写回（浏览器不支持时自动回退为「导出 custom-quiz.js」下载 → 手动覆盖）；
4. 刷新主页面即可看到更新（无需重新构建、无需联网）。

## 12. 已知限制与风险

| 项 | 说明 | 处理 |
| --- | --- | --- |
| 数据文件语法错误 | 脚本解析失败可能不触发 `onerror`（浏览器差异）；`window.__CUSTOM_QUIZ__` 未赋值时无法拦截 | 结构性错误由 `validateQuizData` 兜底（§6.2）；**整体语法错误**（`window.__CUSTOM_QUIZ__` 未挂上）仍表现为「暂未配置」空态，靠编辑器的「校验并预览」提前发现 |
| 数据版本演进 | 未来字段变更需兼容旧数据 | 数据带 `version`（当前 `DATA_VERSION = 1`）；高于支持版本仅提示、不阻断 |
| base64 图片体积 | 大图内联会让数据文件变大 | 建议压缩后再插入；必要时改用 `public/` 相对路径 |
| 无真实鉴权 | 纯静态，编辑器入口无服务端权限 | 定位为「教师工具」，不做伪安全 |
| 单课交付 | 目前仅 `geo01-earth-universe` 落地 | 数据结构通用，可平移至其它课 |

# 第二部分 · 模块练习题可编辑化（v2.0 规划）

> 本部分为**新增需求的设计定稿**，尚未开发。第一部分（M10 课后练习）保持现状，本部分在其基础上扩展。

## 14. 需求与验收目标

**教师诉求**
1. 每个模块（M1–M9）都有「练习」按钮，点击弹出随堂练习；这些题目**要能被教师编辑**，讲完知识点即可当堂练习；
2. 整节课讲完后有「课后练习」，同样**要能被编辑**；
3. 题目编辑器需支持**逐模块编辑** + 课后练习编辑；
4. 编辑器必须**准确知道这门课有多少个模块**，才能把题目**精确映射**到对应模块与课后练习。

**验收目标**
- 教师拿到分发包（zip）→ 双击 `index.html` → 点任一模块「练习」→ 看到的是**可被编辑器改写**的题目；
- 打开 `custom-quiz-editor.html` → 左侧列出 `M1…M9 + 课后练习` → 编辑任一模块 → 导出后刷新主页面即生效；
- 全程**离线、免重建、免联网**（与第一部分同一体验）。

## 16. 总体架构：契约三件套

核心原则：**结构性信息（有哪些模块）在构建期抽取为只读契约；题目内容单独作为可写数据文件；两者用版本号协商。**

```
源 index.html（<section>/practice-btn）        源 lessonData.ts（practices）
        │  构建期抽取器                                  │  构建期导出（仅当目标缺失）
        ▼                                                ▼
dist/lesson-manifest.js  ← 只读契约 ──┐        dist/practice-data.js ← 可写内容 ──┐
dist/custom-quiz-editor.html ─────────┤                                            │
dist/index.html ─────────────────────┘                                            │
        │                                                                          │
        │  编辑器：注入 manifest → 渲染模块树 → 逐模块编辑 → 导出 practice-data.js ──┘
        ▼
主页面：practice-btn 弹窗读 practice-data.js（读不到 → 回退 lessonData.practices）
```

| 文件 | 角色 | 谁生成 | 谁可写 | 版本字段 |
| --- | --- | --- | --- | --- |
| `lesson-manifest.js` | **契约（只读）** | 构建脚本 | ❌ 人不可改 | `version`（契约版本） |
| `practice-data.js` | **内容（可写）** | 构建期导出默认值 / 编辑器 | ✅ 编辑器 / 教师 | `version` + `updatedAt` |
| 运行时 | 消费方 | — | — | `DATA_VERSION`（支持上限） |

> ⚠️ 生成物（manifest）**不得手工写入**——每次构建会重生成并覆盖。要新增功能，改的是**抽取器 + schema**，不是生成物本身。

## 17. 契约一：课程结构清单 `lesson-manifest.js`

**生成时机**：`npm run build:lesson` 时，由构建脚本读取**源** `lessons/<课>/index.html` 抽取。

**Schema**

```ts
interface LessonManifest {
  contract: 'lesson-manifest'
  version: number            // 契约版本，当前 1
  lesson: string             // 课程 id，如 'geo01-earth-universe'
  title: string              // 课程标题
  generatedAt: string        // 生成时间（ISO）
  modules: ManifestModule[]  // 有随堂练习按钮的模块（按出现顺序）
  postLesson: ManifestSection | null  // 末节（无练习按钮），即课后练习
}

interface ManifestModule {
  key: string        // 兼容序号键，如 'M1'（来自 data-practice）
  id: string         // 稳定主键 = 段 id，如 'universe'
  no: string         // 模块序号，如 '01'
  nav: string        // 导航名，如 '宇宙'
  title: string      // 去标签后的模块标题，如 '宇宙概念'
  practice: boolean  // 是否有随堂练习按钮
  kind: 'choice' | 'drag'   // 练习形态；'drag' 表示特殊题型（M3）
}

interface ManifestSection { id: string; no: string; nav: string; title: string }
```

**抽取规则**（构建期 Node 与编辑器 `DOMParser` **共用同一份选择器常量**，避免两边漂移）

| 抽取项 | 选择器 / 规则 |
| --- | --- |
| 模块边界 | `<section class="section" id=… data-nav=…>`；**仅取 class 含 `section` 类名的顶层 section**，排除模块内嵌套的 `<section class="cosmic-panel">`/`life-panel` 等 |
| 序号 | `.section__tag-num` 的 `textContent` |
| 标题 | `.section__title` 的 `textContent`（**去 HTML 标签**，M2 的标题含 `<strong>`） |
| 练习键 | `.practice-btn[data-practice]` 的 `data-practice`（如 `M1`） |
| 练习形态 | 练习按钮的 `data-practice-kind` 属性；缺省为 `choice`。M3 显式标注 `data-practice-kind="drag"` |
| 课后练习 | 无 `.practice-btn` 的末尾 `<section>` → `postLesson` |

| --- | --- | --- | --- | --- | --- | --- |

| M2 | celestial | 02 | 天体 | 天体是宇宙中物质的存在形式 | ✅ | choice |
| M3 | meteor | 03 | 判别 | 天体判别 · 流星案例 | ✅ | **drag** |

| M6 | planets | 06 | 行星 | 行星的运动特征 | ✅ | choice |
| M7 | earth | 07 | 地球 | 地球的普通性和特殊性 | ✅ | choice |
| M8 | life | 08 | 生命 | 地球存在生命的原因 | ✅ | choice |

**抽取器实现（构建期，Node）**

```js
// scripts/manifest.mjs（构建期与编辑器共用 MANIFEST_RULES）
export const MANIFEST_RULES = {
  // 仅顶层模块 section：class 含 section 类名（排除嵌套的 cosmic-panel / life-panel 等）
  section: /<section\b([^>]*\bclass="[^"]*\bsection\b[^"]*"[^>]*)>/g,
  id: /id="([^"]+)"/,
  nav: /data-nav="([^"]+)"/,
  no: /section__tag-num[^>]*>([\s\S]*?)<\//,
  title: /section__title[^>]*>([\s\S]*?)<\/h2>/,
  practiceKey: /data-practice="([^"]+)"/,
  practiceKind: /data-practice-kind="([^"]+)"/
}

export function extractManifest(html, meta = {}) {
  const strip = (s) => (s || '').replace(/<[^>]+>/g, '').replace(/\s+/g, ' ').trim()
  const modules = []
  let postLesson = null
  const heads = [...html.matchAll(MANIFEST_RULES.section)]
  heads.forEach((m, i) => {
    const attrs = m[1] || ''
    const end = heads[i + 1] ? heads[i + 1].index : html.length
    const body = html.slice(m.index, end)
    const id = (attrs.match(MANIFEST_RULES.id) || [])[1] || ''
    const nav = (attrs.match(MANIFEST_RULES.nav) || [])[1] || ''
    if (!id) return
    const no = strip((body.match(MANIFEST_RULES.no) || [])[1])
    const title = strip((body.match(MANIFEST_RULES.title) || [])[1])
    const key = (body.match(MANIFEST_RULES.practiceKey) || [])[1] || ''
    if (!key) { postLesson = { id, no, nav, title }; return }
    const kind = (body.match(MANIFEST_RULES.practiceKind) || [])[1] || 'choice'
    modules.push({ key, id, no, nav, title, practice: true, kind })
  })
  return { contract: 'lesson-manifest', version: MANIFEST_VERSION, lesson: meta.lesson || '', title: meta.title || '', generatedAt: new Date().toISOString(), modules, postLesson }
}
```

> 已实现于 [scripts/manifest.mjs](../../../scripts/manifest.mjs)，单测 [tests/manifest.test.ts](../../../tests/manifest.test.ts)（geo01 应得 9 个 `modules` + 1 个 `postLesson`，M3 为 `drag`）。

## 18. 契约二：练习题内容 `practice-data.js`

**统一题型**：模块随堂练习升级为与课后练习**同构**的题型（`choice` / `essay`），编辑器与渲染器只维护一套。

```js
window.__PRACTICE_DATA__ = {
  version: 1,
  lesson: 'geo01-earth-universe',
  updatedAt: '2026-10-10T…',
  modules: {                       // 键 = manifest 的 id（稳定主键）
    universe:  { title: '宇宙概念 · 随堂练习', intro: '…', questions: [ /* CqQuestion[] */ ] },
    celestial: { … },
    meteor:    { kind: 'drag' },   // 拖拽题：内容仍由源码提供，编辑器只读占位
    …
  },
  postLesson: { title: '自定义练习', subtitle: '…', sections: [ /* CqSection[]，沿用第一部分结构 */ ] }
}
```

**旧数据迁移**（`lessonData.practices` → 新 schema）

| 旧字段 | 新字段 | 规则 |
| --- | --- | --- |
| `PracticeItem.title` | `modules[id].title` | 直接取 |
| `PracticeItem.intro` | `modules[id].intro` | 直接取 |
| `PracticeQuestion.q` | `question.stem` | 直接取 |
| `options: string[]` | `options: { key:'A'…, text }[]` | 按序号生成 key |
| `answer: number` | `answer: 'A'`（字母） | 下标 → 字母；多选 → `string[]` |
| `explain` | `analysis` | 直接取 |

**兼容策略**：运行时 `__PRACTICE_DATA__` 缺失或某模块缺失 → **回退** `lessonData.practices` 的内置题目，保证既不破坏现有页面，也允许"只编辑一部分模块"。

## 22. 版本与兼容

- 三处版本：`manifest.version`（契约）、`practice-data.version`（内容）、运行时 `DATA_VERSION`（支持上限）。
- 规则：**新增字段一律可选**；**未知字段忽略**；**高于支持版本仅提示、不阻断**（沿用第一部分 P3 已实现的模式）。
- 契约与内容解耦：旧编辑器读新数据 → 忽略未知字段；新编辑器读旧数据 → 缺字段走默认值。

## 24. 已确认设计决策（原待确认项）

> 以下为定稿结论，作为 S1–S6 的实现依据。

| # | 决策 | 结论与理由 |
| --- | --- | --- |
| 1 | **课后练习归属** | **沿用现有 M10「自定义练习」**。改动最小、已有外置文件与编辑器、导航已有「练习」入口；在数据模型中标记为 `postLesson` 即可。不新增独立区块。 |
| 2 | **主键** | **以段 `id` 为主键**（`universe`…`review`），`M1…M9` 仅作兼容键。manifest 同时给出 `key` 与 `id`，运行时先按 `id` 查、再按 `key` 兜底 —— 插删模块不会错位。 |
| 3 | **数据真源** | 迁移后 **`lessonData.practices` 保留为兜底（fallback）**，`practice-data.js` 为可编辑真源；一个版本后评估是否删除源码兜底。理由：零破坏、支持"只编辑部分模块"、数据缺失/损坏时不空白。 |
| 4 | **旧题迁移** | 由**一次性迁移脚本**（`scripts/migrate-practice.mjs`，幂等、可重跑）把 `lessonData.practices` 转为 `lessons/<课>/public/practice-data.js` 并**提交**（与 `custom-quiz.js` 同一模式）。构建**不再生成/覆盖**该文件，避免冲掉教师改动。 |
| 5 | **M3 拖拽题** | 编辑器**只读占位**（`kind:'drag'`），内容仍由源码 `dragCards` 提供；不做可视化编辑（成本高、收益低）。 |
| 6 | **清单获取** | **manifest 为主 + 拖入 `index.html` 解析为回退**，两端共用同一套抽取规则（`MANIFEST_RULES`）。 |

**由决策 4 带来的构建口径修正**：`practice-data.js` 与 `custom-quiz.js` 一样，属于**提交在 `public/` 的可编辑数据文件**，由 `public/` → `dist/` 的原样复制进入分发包；构建脚本**只生成 `dist/lesson-manifest.js`**（结构契约），不生成数据文件。
