# 练习题编辑与课程渲染系统重构开发文档

> 本文用于指导 AI 或开发者对现有练习题系统进行重构。  
> 重构目标是：让教师能够像使用 Word/PPT 一样排版题目材料，同时保证课程网页可以准确渲染材料，题目选项仍然可以点击、判题和显示解析。

---

# 1. 项目背景

当前系统具有以下基础能力：

- 每堂课对应一个独立的 `practice-data.js`；
- 课程页面通过：

```js
window.__PRACTICE_DATA__
```

读取题库数据；

- 题目使用结构化 JSON 保存；
- `material`、`analysis`、`referenceAnswer` 等字段使用 HTML；
- 课程侧通过 `openPracticeWindow()` 打开练习窗口；
- 题目通过 `renderQuestionCard()` 渲染；
- 编辑器和课程预览共用运行时；
- 支持离线分发；
- 图片目前主要以内联 Base64 形式存在；
- 当前数据存在 v2 扁平结构和 v3 题组结构并存的问题。

当前富文本编辑器无法很好满足以下需求：

- 图片自由拖动；
- 图片单独缩放；
- 多张图片并排；
- 图片与表格并排；
- 图片在左、文字在右；
- 表格与图片组成类似 Word/PPT 的复杂材料；
- 编辑器中显示效果与课程页面最终效果一致。

因此本次重构不再继续扩展普通富文本编辑器来实现完整自由排版，而是引入：

> **结构化题目数据 + 自由布局材料画布 + 公共材料渲染器 + 结构化可交互题目渲染器**

---

# 2. 重构目标

## 2.1 必须实现的能力

### 材料编辑能力

材料区域需要支持：

- 普通文字；
- 加粗、斜体、下划线；
- 表格；
- 图片；
- 多张图片并排；
- 图片自由拖动；
- 图片自由缩放；
- 图片保持宽高比缩放；
- 图片左对齐、居中、右对齐；
- 图片与文字左右排列；
- 表格与图片左右排列；
- 两栏、三栏；
- 对象复制、删除；
- 对象层级调整；
- 撤销、重做；
- 编辑器实时预览；
- 保存后课程页面准确还原布局。

### 题目能力

继续支持：

- 单选题；
- 简答题/综合题；
- 公共材料对应多道题；
- 选项点击；
- 判题；
- 正确答案；
- 解析；
- 参考答案；
- 题目排序；
- 题组编辑。

### 数据能力

继续支持：

- 每堂课一个题库文件；
- 离线运行；
- `file://` 环境下使用；
- 题库使用经典脚本注入；
- 课程页面不需要 `fetch()` 题库；
- 编辑器导出 `practice-data.js`；
- 课程页面和编辑器使用同一份数据；
- 编辑器预览和课程实际展示共用渲染器。

---

## 2.2 明确不在本次重构范围内的能力

本次不实现：

- 多人协作；
- 云端题库；
- 历史版本；
- 草稿服务器；
- 跨课程题目引用；
- 完整 Word 文档流；
- 完整 PPT 动画；
- 任意角度旋转；
- 多页自动分页；
- 复杂文字环绕；
- 导出 `.docx`；
- 导出 PDF；
- 移动端编辑器适配。

当前优先实现：

> **电脑端、单人、离线、PPT 式自由布局材料编辑。**

---

# 3. 总体设计

最终架构：

```text
每课 practice-data.js
        │
        ▼
window.__PRACTICE_DATA__
        │
        ▼
practiceStore
        │
        ▼
openPracticeWindow()
        │
        ├── renderGroup()
        │     │
        │     ├── MaterialRenderer
        │     │     └── 材料画布
        │     │
        │     └── QuestionRenderer
        │           ├── 题干
        │           ├── 选项
        │           ├── 判题
        │           └── 解析
        │
        └── 运行时交互
```

数据关系：

```text
PracticeData
└── modules
    └── PracticeModule
        └── groups
            ├── materialLayout
            │   └── objects[]
            │       ├── text
            │       ├── image
            │       └── table
            │
            └── questions[]
                ├── choice
                └── essay
```

核心原则：

1. **材料和题目分离；**
2. **公共材料只保存一次；**
3. **材料使用自由布局对象；**
4. **题目和选项继续结构化保存；**
5. **选项不能做成普通文本画布对象；**
6. **编辑器和课程页面共用同一个渲染器；**
7. **只保留 v3 作为正式落盘格式；**
8. **旧 v2 只在读取时兼容，不再导出。**

---

# 4. 数据格式重构

## 4.1 顶层数据格式

正式格式统一为 v3：

```js
window.__PRACTICE_DATA__ = {
  version: 3,
  lesson: 'geo01-earth-universe',
  updatedAt: '2026-10-31T12:00:00.000Z',

  modules: {
    universe: {
      id: 'universe',
      title: '宇宙',
      intro: '<p>本模块练习</p>',
      groups: [
        {
          id: 'universe-group-1',
          layout: 'stacked',
          materialLayout: null,
          questions: []
        }
      ]
    }
  },

  postLesson: {
    title: '课后练习',
    subtitle: '',
    sections: []
  }
};
```

正式保存时：

- 使用 `groups`；
- 不再保存模块级扁平 `questions`；
- 不再同时保存 `groups` 和 `questions`；
- 不再把组材料复制到每一道题的 `material` 字段。

---

## 4.2 题组结构

```ts
interface CqGroup {
  id: string;
  title?: string;

  /**
   * stacked:
   *   材料在上，题目在下
   *
   * split:
   *   材料和题目左右分栏
   */
  layout?: 'stacked' | 'split';

  material?: string;
  materialLayout?: MaterialLayout | null;

  questions: CqQuestion[];
}
```

说明：

- `materialLayout` 是新格式；
- `material` 是旧 HTML 材料字段，仅用于兼容旧题；
- 新编辑器默认只生成 `materialLayout`；
- 如果题组没有自由布局材料，可以为 `null`；
- 如果题组有旧材料 HTML，运行时继续支持。

---

## 4.3 选择题结构

```ts
interface CqChoice {
  id?: string;
  type: 'choice';
  mode: 'single';

  stem: string;

  options: Array<{
    key: string;
    text: string;
  }>;

  answer: string;
  analysis?: string;
}
```

约束：

- `stem` 为纯文本或经过现有约定处理的安全内容；
- `options[].text` 为文本；
- `answer` 为单个选项字母；
- 新编辑器不产生多选数组；
- 旧数组答案只在读取时兼容；
- 选项必须使用结构化按钮渲染。

---

## 4.4 简答题/综合题结构

```ts
interface CqEssay {
  id?: string;
  type: 'essay';

  stems: string[];

  referenceAnswer?: string;
  analysis?: string;
}
```

# 5. 自由布局材料模型

## 5.1 MaterialLayout

```ts
interface MaterialLayout {
  version: 1;

  /**
   * 编辑器内部逻辑画布尺寸。
   * 不直接使用浏览器实时像素。
   */
  width: number;
  height: number;

  background?: string;

  objects: MaterialObject[];
}
```

默认画布尺寸：

```js
{
  width: 1000,
  height: 520
}
```

推荐原因：

- 容易在编辑器中显示；
- 适合“几行文字 + 表格 + 图片”；
- 可以响应式缩放；
- 方便以后导出；
- 不依赖具体浏览器大小。

---

## 5.2 基础对象结构

```ts
interface BaseMaterialObject {
  id: string;

  type: 'text' | 'image' | 'table';

  x: number;
  y: number;
  width: number;
  height: number;

  zIndex?: number;

  visible?: boolean;
}
```

所有坐标和尺寸必须是有限数字：

```text
x >= 0
y >= 0
width > 0
height > 0
```

---

## 5.3 文字对象

```ts
interface TextMaterialObject extends BaseMaterialObject {
  type: 'text';

  html: string;

  style?: {
    fontFamily?: string;
    fontSize?: number;
    fontWeight?: 'normal' | 'bold';
    lineHeight?: number;
    textAlign?: 'left' | 'center' | 'right';
    verticalAlign?: 'top' | 'middle' | 'bottom';
    color?: string;
  };
}
```

示例：

```js
{
  id: 'text-001',
  type: 'text',
  x: 30,
  y: 20,
  width: 940,
  height: 100,
  html: `
    <p>老城南地区位于南京市内城南部，经过持续更新改造，已成为城市新名片。</p>
    <p>下图示意老城南地区历史要素的空间分布。</p>
  `,
  style: {
    fontSize: 22,
    lineHeight: 1.7,
    textAlign: 'left'
  }
}
```

文字对象内部可以继续使用 SunEditor 或现有富文本组件。

重要限制：

> 文字对象内部可以包含文字格式，但不建议在文字 HTML 中保存自由定位的图片或表格。

图片和表格应作为独立对象保存。

---

## 5.4 图片对象

```ts
interface ImageMaterialObject extends BaseMaterialObject {
  type: 'image';

  src: string;
  alt?: string;

  objectFit?: 'contain' | 'cover' | 'fill';

  lockAspectRatio?: boolean;

  style?: {
    objectPosition?: string;
    border?: string;
  };
}
```

示例：

```js
{
  id: 'image-001',
  type: 'image',
  x: 655,
  y: 145,
  width: 310,
  height: 330,
  src: './assets/laochengnan-map.png',
  alt: '老城南地区历史要素空间分布图',
  objectFit: 'contain',
  lockAspectRatio: true
}
```

---

## 5.5 表格对象

第一阶段允许使用安全 HTML：

```ts
interface TableMaterialObject extends BaseMaterialObject {
  type: 'table';

  html: string;
}
```

示例：

```js
{
  id: 'table-001',
  type: 'table',
  x: 30,
  y: 145,
  width: 600,
  height: 330,
  html: `
    <table>
      <tr>
        <th>更新方式</th>
        <th>案例</th>
      </tr>
      <tr>
        <td>复建古建筑群；历史文化空间的整体仿真</td>
        <td>夫子庙</td>
      </tr>
    </table>
  `
}
```

表格 HTML 必须经过：

```ts
sanitizeHtml()
```

禁止：

- `script`；
- `style`；
- 事件属性；
- `iframe`；
- 任意危险 URL；
- 未授权 CSS。

后续如果需要复杂表格编辑，再将表格逐步结构化。

# 7. 课程网页渲染方案

## 7.1 课程侧职责

课程页面只负责：

1. 加载本课程的 `practice-data.js`；
2. 读取 `window.__PRACTICE_DATA__`；
3. 根据模块 ID 找到对应题组；
4. 调用公共运行时；
5. 不直接处理材料对象；
6. 不直接处理题目点击逻辑。

课程侧不应该自行编写：

```text
图片渲染
表格渲染
题目按钮
判题
解析
计时
预览
```

这些全部属于 `shared/quiz` 公共层。

---

## 7.2 推荐调用方式

```ts
const data = getPracticeData();
const moduleData = data.modules[moduleId];

openPracticeWindow({
  title: moduleData.title,
  groups: moduleData.groups || [],
  display: 'overlay',
  mode: 'group',
  timer: true
});
```

如果仍需要兼容旧模块：

```ts
const groups = moduleData.groups?.length
  ? moduleData.groups
  : normalizeLegacyQuestions(moduleData.questions || []);

openPracticeWindow({
  title: moduleData.title,
  groups,
  display: 'overlay'
});
```

# 8. 题组渲染方案

新增或重构：

```text
shared/quiz/content/renderGroup.ts
```

接口：

```ts
interface RenderGroupOptions {
  group: CqGroup;
  startQuestionIndex?: number;
  mode?: 'view' | 'preview';
  showAnalysis?: boolean;
}
```

核心逻辑：

```ts
function renderQuestionGroup(options: RenderGroupOptions): HTMLElement {
  const { group } = options;

  const root = document.createElement('section');
  root.className = `cq-group cq-group--${group.layout || 'stacked'}`;

  if (group.materialLayout) {
    const material = renderMaterialLayout(group.materialLayout, {
      mode: 'view'
    });

    material.classList.add('cq-group__material');
    root.appendChild(material);
  } else if (group.material) {
    const material = renderLegacyMaterial(group.material);
    material.classList.add('cq-group__material');
    root.appendChild(material);
  }

  const questions = document.createElement('div');
  questions.className = 'cq-group__questions';

  group.questions.forEach((question, index) => {
    questions.appendChild(
      renderQuestionCard({
        question,
        index,
        layout: 'stacked'
      })
    );
  });

  root.appendChild(questions);

  return root;
}
```

# 11. 编辑器重构方案

## 11.1 编辑器交互模型

材料编辑器采用：

```text
DOM 画布
+ position:absolute
+ interact.js 拖动/缩放
+ SunEditor 文字编辑
```

不使用 Canvas 作为主要渲染层。

原因：

- 文字编辑更简单；
- 表格继续使用 HTML；
- 课程页面可以复用同一套 DOM 渲染；
- 题目选项仍能保持结构化；
- 离线打包容易；
- 更容易处理 HTML 清洗。

---

## 11.2 编辑器布局

```text
┌───────────────────────────────────────────────┐
│ 文件 编辑 插入 格式                           │
├───────────────────────────────────────────────┤
│ 撤销 重做 | 文本 | 图片 | 表格 | 对齐 | 删除    │
├────────────┬──────────────────────┬───────────┤
```

# 12. 编辑器状态模型

编辑器状态示例：

```ts
interface EditorState {
  data: PracticeData;

  selectedGroupId: string | null;
  selectedQuestionId: string | null;
  selectedObjectId: string | null;

  history: {
    past: PracticeData[];
    future: PracticeData[];
  };
}
```

任何修改都必须更新结构化数据，而不是只修改 DOM：

```ts
function updateMaterialObject(
  groupId: string,
  objectId: string,
  patch: Partial<MaterialObject>
) {
  const group = findGroup(groupId);
  const object = group.materialLayout?.objects
    .find(item => item.id === objectId);

  if (!object) return;

  Object.assign(object, patch);
  saveHistory();
  refreshPreview();
}
```

DOM 只是视图，JSON 才是唯一真实状态。

# 13. 拖动和缩放实现

可以使用 `interact.js`。

示意代码：

```js
interact('.cq-material-editor__object')
  .draggable({
    listeners: {
      move(event) {
        const target = event.target;

        const objectId = target.dataset.materialObjectId;
        const object = getObject(objectId);

        if (!object) return;

        object.x += event.dx / currentScale;
        object.y += event.dy / currentScale;

        clampObject(object, currentLayout);

        renderObjectPosition(target, object);
        markDirty();
      }
    }
  })
  .resizable({
    edges: {
      left: true,
      right: true,
      top: true,
      bottom: true
    },

    listeners: {
      move(event) {
        const target = event.target;
        const objectId = target.dataset.materialObjectId;
        const object = getObject(objectId);

        if (!object) return;

        updateObjectSizeFromResize(object, event);
        clampObject(object, currentLayout);

        renderObjectRect(target, object);
        markDirty();
      }
    }
  });
```

重要要求：

- 实际坐标必须除以当前缩放比例；
- 不能把浏览器缩放后的像素直接保存；
- 对象不能拖出画布；
- 宽高不能小于最小值；
- 图片锁定比例时必须保持原始比例。

# 18. 校验方案

新增：

```ts
validateMaterialLayout(layout)
```

校验内容：

```text
layout 必须是对象
version 必须为 1
width / height 必须为正数
objects 必须为数组
对象数量不能超过限制
id 必须唯一
x / y / width / height 必须是有限数字
type 必须是 text/image/table
text 必须有 html
image 必须有 src
table 必须有 html
HTML 必须通过 sanitizeHtml
图片协议必须安全
```

建议对象限制：

```text
最大画布宽度：3000
最大画布高度：3000
单个题组最多对象数：100
单个图片 Base64 大小：建议不超过 5MB
```

异常处理：

- 材料布局非法：忽略该布局，显示空材料状态；
- 单个对象非法：跳过该对象；
- 图片加载失败：显示图片占位符；
- HTML 清洗失败：显示清洗后的安全内容；
- 不能因为单个对象损坏导致整个练习页面白屏。

最终达到的效果是：

```text
教师在编辑器中像 PPT/Word 一样排材料

              ↓
```

这套方案既保留了当前系统已经完成的离线加载、题目判题、运行时窗口和统一预览能力，又能增加接近 Word/PPT 的材料排版能力，适合当前每课 5～10 道题、电脑端编辑、非技术教师使用的实际场景。
