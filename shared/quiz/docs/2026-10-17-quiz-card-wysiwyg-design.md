## 1. 意图

教师改题时，应该直接看到**学生在真实课程页面里看到的效果**，而不是一套近似的预览。

当前的问题是：

- 题库内容用 Markdown 子集存储，运行时再转成网页；编辑器预览又是另一套近似渲染。
- 编辑器预览、运行时渲染、实验件 `QuizContent` 是三套实现，长期必然漂移。
- 新课程若复制卡片代码，会出现多份副本，改一次要改多课。

本设计要收敛成一件事：**卡片只做一份，内容只存 HTML，编辑器整窗预览与真实课程共用同一套渲染和样式。**

---

## 2. 目标与非目标

### 2.1 目标

1. 教师编辑器内的预览，与真实课程中的**全屏答题窗口**一致：卡片、配色、字号、圆角、毛玻璃、题号导航、计时、重做入口都一致。
2. 题目内容统一存为**经过白名单清洗的 HTML**，不再使用 Markdown。
3. 公共答题卡片只维护一份源码，课程构建时自动带入，不在单课复制。
4. 每门课有一份独立配色表，卡片代码不变，只换颜色、圆角、字体、字号。
5. 题库文件与配色表分离：教师替换题库不会影响课程配色。
6. 继续支持离线双击分发（`file://`），教师换题不需要重新构建、不需要联网。

### 2.2 非目标

- 学生作答数据的收集、统计、上传。
- 在线协同编辑、账号体系。
- 教师自行修改课程配色（配色由课程开发时确定）。
- 保留 Markdown 兼容层。
- 在本阶段支持拖拽题等特殊题型的可视化编辑。

### 2.3 失败标准

- 编辑器预览与真实课程仍由两套渲染实现，效果需要人工对齐。
- 新课程需要复制卡片源码。
- 教师在题库文件里能意外改掉课程配色。
- 旧 Markdown 数据迁移后出现内容丢失或样式塌陷。
- 离线双击打开后，题库或预览无法工作。

## 3. 已确认决策

| # | 决策 | 结论 |
| --- | --- | --- |
| D1 | 内容格式 | 一次性迁移为 HTML，删除 Markdown 渲染，不做双模兼容 |
| D2 | 题库载体 | 仍是 `practice-data.js`，运行时通过经典 `<script src>` 注入并读取全局变量；不使用 `fetch` JSON |
| D3 | 卡片归属 | 卡片是公共源码，单课构建时引用并带入产物，禁止在单课源码中复制 |
| D4 | 配色归属 | 每课一份配色表，写最终色值；与题库文件分离；教师不可改 |
| D5 | 预览保真度 | 编辑器预览必须呈现**全屏答题窗口整窗效果**，不只预览单张卡片 |
| D6 | 编辑器形态 | 编辑器改为构建生成，但产物仍是一个可双击的离线单文件 |
| D7 | 首个课程 | `geo01-earth-universe`，因为其练习链路已完整接入 |
| D8 | 富文本范围（第一阶段） | 材料、解析、参考答案、评分标准支持富文本；题干与选项先保持纯文本 |
| D9 | 整窗预览方式 | 在编辑器内用固定设计画布（1920×1080）+ 缩放呈现；运行时增加“嵌入展示”模式，避免整窗遮住编辑器 |
| D10 | 主题来源 | 编辑器只加载**自身所在课程**的配色表，不提供跨课程切换；配色不写入题库，教师不可改 |
| D11 | 公共层自包含 | 公共卡片与运行时不得依赖任何单课类名（如 `btn` / `panel`）；所需样式与令牌全部收进公共层 |

## 4. 目标结构

```text
shared/quiz/
├─ content/                 卡片与内容渲染（唯一真源）
│   ├─ sanitize.ts          HTML 白名单清洗
│   ├─ renderCard.ts        题目卡片渲染
│   ├─ card.css             卡片结构样式
│   └─ types.ts             内容契约
├─ runtime/                 练习窗口（已由 shared/practice-window 迁入）
│   ├─ practiceWindow.ts    窗口骨架、交互、整窗/嵌入两种展示
│   ├─ validate.ts
│   ├─ types.ts
│   └─ styles/
├─ editor/                  教师编辑器（已由 shared/custom-quiz-editor 迁入）
│   ├─ src/
│   └─ build/               构建为单文件 HTML
└─ docs/

lessons/<课>/
├─ src/styles/quiz-theme.css      本课配色表（显式色值）
├─ public/quiz-editor/practice-data.js  本课题库（HTML 内容）
└─ index.html                     引用公共卡片与题库
```

说明：目录合并是推荐形态，不是本设计的前置条件；可以先抽取 `content` 与 `runtime`，编辑器迁移放到后续阶段。但“单一真源、禁止复制”是硬约束。

## 5. 数据契约

### 5.1 题库文件

文件名与读取方式保持不变：

```js
window.__PRACTICE_DATA__ = {
  version: 2,
  lesson: 'geo01-earth-universe',
  updatedAt: '...',
  modules: { /* 键 = 模块 id */ },
  postLesson: { /* 课后练习 */ }
}
```

运行时仍由 `practiceStore` 注入 `./quiz-editor/practice-data.js` 并读取全局变量。原因：离线双击时 `fetch` 会被浏览器拦截，经典脚本不受影响。

### 5.2 题目字段

题型结构不变，长文本字段从 Markdown 改为 HTML：

| 字段 | 格式 | 说明 |
| --- | --- | --- |
| `material` | HTML | 材料，可含段落、列表、表格、图片、分栏 |
| `stem` | 纯文本 | 题干；第一阶段不支持富文本 |
| `options[].text` | 纯文本 | 选项；第一阶段不支持富文本 |
| `analysis` | HTML | 解析 |
| `referenceAnswer` | HTML | 参考答案 |
| `criteria[]` | HTML | 评分标准条目 |
| `stems[]` | 纯文本 | 综合题设问 |
| `knowledge.title` | 纯文本 | 补充说明标题 |
| `knowledge.items[]` | HTML | 补充说明条目 |

### 5.3 HTML 白名单

沿用实验件已经验证的契约：

- 允许：段落、换行、加粗、斜体、下划线、删除线、上下标、**行内标记（`mark`）**、**行内代码（`code`）**、图片、链接、有序/无序列表、表格、图注、三级/四级标题、分栏容器。
- 属性只保留：图片地址与替代文字、链接地址、表格合并格、段落对齐、图片宽度。
- 类名只保留 `cq-` 前缀；关键词高亮统一使用 `cq-hl`，分栏保留 `cq-cols` / `cq-col`。
- 脚本、样式表、内嵌框架、事件属性一律剥除。
- 未知标签剥壳保留文字；未知类名剥除。

清洗发生在**运行时渲染前**，编辑器导出时也执行一次，保证数据文件本身尽量干净。

### 5.4 旧数据迁移

对 `lessons/geo01-earth-universe/public/quiz-editor/practice-data.js` 做一次性迁移：

| Markdown | HTML |
| --- | --- |
| `**加粗**` | `<strong>` |
| `*斜体*` | `<em>` |
| `` `代码` `` | `<code>` |
| `==关键词==` | `<mark class="cq-hl">关键词</mark>` |
| `![说明](路径)` | `<img src="路径" alt="说明">` |
| `[文字](链接)` | `<a href="链接">文字</a>` |
| 表格 | `<table>` |
| `- ` / `1. ` 列表 | `<ul>` / `<ol>` |
| 连续段落 | `<p>`，段内换行 `<br>` |

迁移后逐题校验，确保题干、选项、答案、解析完整；迁移脚本幂等，可重复运行。

### 5.5 无标签内容的兜底

如果某个字段没有任何 HTML 标签（教师直接输入纯文字），运行时按纯文本处理：转义后保留换行。**不启用 Markdown 解析**，避免两套语义。

## 6. 配色契约

### 6.1 原则

卡片结构、交互、布局属于公共代码；颜色、圆角、字体、字号属于课程。课程只覆盖设计令牌，不覆盖卡片内部类名。

**公共层必须自包含**：答题窗口用到的按钮、面板、标题、导航等样式全部随公共层提供，不得引用单课样式里的 `btn`、`panel` 等类名。否则编辑器或新课程会因缺少单课样式而变形。

### 6.2 每课一份完整配色表

配色表必须写全下面这组令牌，且写**最终值**，不引用其他变量：

| 类别 | 必需令牌 |
| --- | --- |
| 主色与状态 | `--pw-accent`、`--pw-accent-2`、`--pw-accent-text`、`--pw-success`、`--pw-error`、`--pw-warn` |
| 表面与描边 | `--pw-surface`、`--pw-border`、`--pw-panel-bg`、`--pw-overlay-bg`、`--pw-material-bg` |
| 文字 | `--pw-text`、`--pw-text-dim` |
| 形状 | `--pw-radius-card`、`--pw-radius-btn` |
| 字体 | `--pw-font`、`--pw-fs-body`、`--pw-fs-note`、`--pw-fs-h3` |
| 动效 | `--pw-dur`、`--pw-ease` |
| 毛玻璃 | `--pw-backdrop-blur` |

```css
/* lessons/<课>/src/styles/quiz-theme.css */
.pw {
  --pw-accent: #FFD54F;
  --pw-accent-2: #4FC3F7;
  --pw-accent-text: #BFE9FF;
  --pw-success: #66BB6A;
  --pw-error: #EF5350;
  --pw-warn: #FFB74D;
  --pw-surface: rgba(255, 255, 255, 0.06);
  --pw-border: rgba(255, 255, 255, 0.14);
  --pw-panel-bg: rgba(13, 18, 40, 0.55);
  --pw-overlay-bg: rgba(4, 7, 20, 0.55);
  --pw-material-bg: rgba(11, 16, 38, 0.55);
  --pw-text: #E8EAF6;
  --pw-text-dim: rgba(232, 234, 246, 0.7);
  --pw-radius-card: 16px;
  --pw-radius-btn: 10px;
  --pw-font: "SourceHanSansSC", "Microsoft YaHei", sans-serif;
  --pw-fs-body: 20px;
  --pw-fs-note: 16px;
  --pw-fs-h3: 24px;
  --pw-dur: 0.35s;
  --pw-ease: cubic-bezier(0.25, 0.8, 0.35, 1);
  --pw-backdrop-blur: 22px;
}
```

要求：

- 配色表只作用于答题窗口，不影响课程其他部分。
- 配色表随课程构建进入产物，同时复制一份到 `dist/` 供编辑器预览读取。
- 构建校验必须检查必需令牌是否齐全，缺项时报错，不允许静默回退。

### 6.3 默认令牌只作中性兜底

公共层自带一套中性默认值，只用于课程尚未提供配色表时的可读性兜底，**不再映射到单课令牌**。真实课程与编辑器预览都以课程配色表为准。

### 6.4 已知差异

`geo01-earth-universe` 使用金色/青色令牌；`geo-sp01-space-launch` 使用另一套命名与色值。因此不能依赖自动识别，必须每课显式提供配色表。这是本设计选择“显式配色表”的直接原因。

### 6.5 编辑器的主题来源

编辑器只读取**自身所在课程**的配色表：

- 编辑器被复制到某课 `dist/` 时，同时带上该课的配色表；
- 不提供跨课程切换，避免在离线单文件下加载其他课程资源；
- 配色不写入题库，教师不可修改。

## 7. 整窗预览设计

### 7.1 预览形态

编辑器提供两种视图：

1. **编辑视图**：左侧分组、中间表单、右侧整窗预览（可折叠/切换到底部）。
2. **沉浸预览**：预览区放大到接近全屏，仍保留返回编辑的入口。

### 7.2 为什么需要“嵌入展示”模式

真实答题窗口是固定定位、铺满浏览器视口的。如果在编辑器页面里直接打开，它会盖住整个编辑器，教师无法边看边改。

因此运行时增加一个展示模式：

- `overlay`：真实课程使用，铺满视口，行为不变。
- `embedded`：编辑器预览使用，窗口铺满一个指定的“预览画布”，而不是整个浏览器。

两种模式共用同一套窗口结构、卡片渲染、样式和交互，只是定位参照不同。

### 7.3 预览画布

- 画布按 1920×1080 设计，等比缩放到编辑器可用空间。
- 画布背景模拟课程页面的深色底，保证半透明与毛玻璃效果可判断。
- 提供缩放档位：适应宽度、50%、100%。
- 画布内呈现完整窗口，包括标题、题号导航、左右双栏；其余控件按下方预设决定。

### 7.4 预览预设必须匹配真实调用形态

`geo01` 的两个真实调用点形态不同，预览不能一律套用同一种：

| 编辑对象 | 真实形态 | 预览预设 |
| --- | --- | --- |
| M1–M9 随堂练习 | 全屏浮层 | 有计时、有关闭、有底部重做、无全屏按钮 |
| M10 课后练习 | 页内挂载 | 无计时、无关闭、无底部重做（区块头部已有重置） |

编辑器默认按当前分组自动选择预设，并提供一个“按真实形态 / 强制整窗”的切换，方便教师对照。预设参数与课程真实调用点保持一致，不另造一套。

### 7.5 预览内的交互

- 教师可以真实点选选项、提交多选、展开参考答案，验证判定与解析效果。
- 计时器真实走动；数据变更后自动重置作答状态并重新渲染。
- 关闭按钮关闭预览并回到编辑视图；全屏按钮让画布进入浏览器全屏。
- 预览始终渲染**当前选中的分组或课后练习**，而不是整本题库。

### 7.6 保真验收清单

- 卡片背景、描边、圆角、阴影一致。
- 正确答案、错误答案、选中态、降噪态颜色一致。
- 材料高亮、表格、图片、分栏的排版一致。
- 字号、行高、左右双栏与窄屏堆叠规则一致。
- 题号导航、计时、重做入口的有无与位置跟真实形态一致。
- 半透明面板与背景模糊效果一致。

## 8. 编辑器架构

### 8.1 构建形态

编辑器改为由构建生成单文件：

- 源码可以引用公共卡片、清洗器和样式；
- 构建后把脚本与样式内联，仍是一个可双击打开的 HTML；
- 不引入运行时网络依赖；
- 富文本编辑器所需的第三方库随产物本地内联或放在同目录，离线可用。

这是为了满足“预览与真实课程共用同一套渲染”的必要代价。若继续手工维护单文件，就只能复制渲染逻辑，违背本设计目标。

### 8.2 职责边界

| 部分 | 职责 |
| --- | --- |
| 公共内容层 | 清洗 HTML、渲染题目卡片 |
| 公共运行时 | 窗口骨架、导航、计时、判定交互、两种展示模式 |
| 编辑器 | 表单、分组树、校验、导入导出、预览装配、主题切换 |
| 课程 | 页面结构、配色表、题库文件 |

编辑器不重新实现卡片的结构与样式。

## 10. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 编辑器从手写单文件改为构建产物 | 改造量大，可能影响现有分发 | 分步进行：先抽公共层，再改编辑器；产物仍为单文件并做离线双击验证 |
| HTML 迁移丢失内容 | 旧题损坏 | 迁移脚本幂等 + 逐题校验 + 迁移前后人工抽查 |
| 整窗预览与真实视口仍有差异 | 预览失真 | 固定 1920×1080 设计画布 + 等比缩放；以保真清单验收 |
| 富文本库体积与许可 | 包体增大 | 仅教师端使用；本地内联；保留 MIT 许可说明 |
| 主题表遗漏或写错 | 预览与课程不一致 | 每课一份显式色值表；构建时检查必需令牌是否齐全 |
| 公共层仍依赖单课类名 | 编辑器或新课程样式塌陷 | 公共层自包含；校验禁止引用 `lessons/**` 样式；窗口控件统一使用 `pw-*` 类名 |
| 单课复制卡片源码 | 多份副本漂移 | 项目规范写明禁止复制；验收检查公共卡片只有一份 |

## 11. 验收标准

1. 教师在编辑器中打开整窗预览，看到的窗口与真实课程中的答题窗口一致，并可直接作答。
2. 题库文件中不再出现 Markdown 语法；运行时不再包含 Markdown 渲染代码。
3. 更换题库文件后，真实课程内容更新，配色不变。
4. 已接入公共运行时的课程，新增题库只需配色表与题库；全新课程需要一次入口接入，但不需要复制卡片代码。
5. 分发包在 `file://` 下双击可用，无需联网、无需重新构建。
6. 现有 geo01 的全部随堂练习与课后练习功能不回退。
