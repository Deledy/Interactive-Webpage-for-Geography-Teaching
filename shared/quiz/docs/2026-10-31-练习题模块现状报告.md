## 0. 摘要

`shared/quiz` 是「练习题展示 + 教师编辑」的公共模块，由三层组成：

| 层 | 目录 | 职责 | 是否与课程耦合 |
| --- | --- | --- | --- |
| 内容层 | `content/` | 数据契约、HTML 清洗、题目卡片渲染、卡片样式 | 不耦合 |
| 运行时层 | `runtime/` | 练习窗口骨架、交互状态机、校验、整窗预览画布 | 不耦合（只消费 `--pw-*` 令牌） |
| 编辑器层 | `editor/` | 教师可视化编辑、导入导出、草稿、实时整窗预览 | 不耦合（文案/文件名/选择器均可配置） |

关键数字（本次实测）：

| 指标 | 数值 |
| --- | --- |
| 源码/样式/文档文件 | 22 个（不含 `build/index.html`） |
| 编辑器单文件产物 | `build/index.html` 1,136,058 字节（约 1.08 MiB） |
| 数据契约版本 | `DATA_VERSION = 3`（题组 `groups` / 节材料） |
| geo01 实际题库 | `version: 2`，9 个模块、9 道题（6 选择 + 3 综合）、**0 个题组**、课后练习 2 题 |
| 自动化测试 | 9 个测试文件、**109 项全部通过**；其中练习相关 49 项 |
| 工程校验 | `tsc --noEmit` 通过；`npm run check` 0 错误、2 条远程 URL 警告（与练习模块无关） |

一句话判断：**展示链路成熟、编辑链路可用，但数据结构正处于「v2 扁平题」向「v3 题组」迁移的半途，编辑器会在打开/保存时自动改写结构，这是当前最需要收口的地方。**

职责边界清晰：

- **内容层**只回答「一道题长什么样」，不依赖运行时、不依赖任何单课样式。

- **编辑器层**只回答「怎么改、怎么存、怎么预览」，预览直接调用运行时，不另写一套渲染。

## 2. 数据契约

### 2.1 顶层结构

题库文件是经典脚本，不是 JSON 文件：

```js
window.__PRACTICE_DATA__ = {
  version: 2,
  lesson: 'geo01-earth-universe',
  updatedAt: '...',
  modules: {
    universe: { title, intro, questions: [...] }   // v2 扁平结构
    // 或 { title, intro, groups: [{ material, questions: [...] }] }  // v3 题组结构
  },
  postLesson: {
    title, subtitle,
    sections: [{ id, title, material, questions: [...] }]
  }
}
```

契约定义在 [types.ts](../content/types.ts)：

| 类型 | 关键字段 | 说明 |
| --- | --- | --- |
| `PracticeData` | `version` / `lesson` / `modules` / `postLesson` | 课程侧再导出，见 `lessons/<课>/src/types.ts` |
| `PracticeModule` | `title` / `intro` / `kind` / `groups` / `questions` | `kind:'drag'` 为拖拽题占位，编辑器只读 |
| `CqSection` | `id` / `title` / `material` / `questions` | 课后练习分节；节材料全节共用 |
| `CqGroup` | `id` / `material` / `questions` | 题组；材料组内共用 |
| `CqChoice` | `type:'choice'` / `mode` / `material` / `stem` / `options` / `answer` / `analysis` | `mode` 仅遗留多选兼容 |
| `CqEssay` | `type:'essay'` / `material` / `stems` / `referenceAnswer` / `analysis` | 综合题 |

### 2.2 字段格式：结构化 JSON + 富文本字段内嵌 HTML

题目不是整段 HTML，而是结构化对象；只有长文本字段存 HTML：

| 字段 | 格式 | 运行时处理 |
| --- | --- | --- |
| `material` | HTML | 白名单清洗 |
| `analysis` | HTML | 白名单清洗 |
| `referenceAnswer` | HTML | 白名单清洗 |
| `stem` | 纯文本 | 仅转义 |
| `options[].text` | 纯文本 | 仅转义 |
| `stems[]` | 纯文本 | 仅转义，渲染为有序列表 |
| `section.title` | 纯文本 | 仅转义 |
| `subtitle` / `intro` | 行内富文本 | HTML 清洗或纯文本转义 |

关键词高亮统一写法：`<mark class="cq-hl">关键词</mark>`；材料分栏统一写法：`<div class="cq-cols"><div class="cq-col">…</div></div>`。

### 2.3 版本与兼容

- `DATA_VERSION = 3`（[validate.ts](../runtime/src/validate.ts#L14-L15)）。
- 数据版本高于 3 只提示、不阻断。
- 选择题 `answer` 允许字符串或数组：数组只用于遗留多选数据；编辑器只产出单字母。
- `source` / `knowledge` / `criteria` / `mode` 已标注为「遗留死键，不再渲染」，但仍保留在类型和部分数据里（geo01 中 `knowledge` 7 处、`criteria` 4 处）。

### 2.4 实际数据与契约的偏差（重要）

geo01 的 [practice-data.js](../../../lessons/geo01-earth-universe/public/quiz-editor/practice-data.js) 仍是 **v2 扁平结构**：

- 9 个模块、每题自带 `material`；
- `groups` 使用数为 **0**；
- 编辑器一旦载入，`normalizeModule()` / `toGroups()` 会把「连续且材料相同的题」自动归入题组（[main.js](../editor/src/main.js#L337-L370)）；
- 保存时 `generated()` 输出 **v3**，并且同时写 `groups` 和扁平化 `questions`（[main.js](../editor/src/main.js#L1289-L1329)）。

后果：

1. 教师只要打开编辑器并保存一次，文件结构就会从 v2 变成 v3；
2. 扁平化 `questions` 会把题组材料复制进每道题，材料在文件中出现多次（1 份组材料 + N 份题目材料），文件体积随题组规模增长；
3. 消费方目前同时兼容两种结构，短期无感，但长期是双轨维护成本。

## 3. 内容层：渲染与安全

### 3.1 HTML 白名单清洗（`sanitize.ts`）

| 维度 | 规则 |
| --- | --- |
| 允许标签 | `p br b strong i em u s strike del sub sup span div mark code img a ul ol li table thead tbody tfoot tr td th colgroup col figure figcaption h3 h4` |
| 整段删除 | `script style iframe link meta object embed` |
| 属性白名单 | 图片 `src/alt/width/height/style`；链接 `href/title/target`；表格 `colspan/rowspan/style`；段落/容器 `style` |
| style 白名单 | 只保留 `width / text-align / vertical-align` |
| 类名 | 只保留 `cq-` 前缀 |
| 协议 | 图片仅 `http(s) / data:image / 相对路径`；链接仅 `http(s) / mailto / # / 相对路径` |
| 未知标签 | 剥壳保留文字 |
| 事件属性 | 一律剥除 |

清洗发生在**运行时渲染前**，编辑器导出时也执行一次。测试覆盖脚本/事件剥除、未知标签、类名、style、协议、表格、分栏、图片宽度（17 项）。

### 3.2 内容 → HTML（`richText.ts`）

- `renderRichText`：块级内容。含标签走清洗；纯文本按空行分段、段内换行转 `<br>`；**不解释 Markdown**。
- `renderInlineRich`：行内内容。含标签走清洗；纯文本仅转义。
- 这套「有标签就清洗、没标签就转义」的策略避免了第二套语义，但也意味着教师直接写 Markdown 不会生效。

### 3.3 单题卡片（`renderCard.ts`）

卡片结构固定为「左材料 / 右上题目 / 右下说明」：

```text
.cq-q
└─ .cq-q__panes（grid：41fr / 59fr）
   ├─ .cq-pane--material        材料（无材料时按参数退化为单栏或保留空栏）
   └─ .cq-pane--main
      ├─ .cq-pane__segment--question   题号 + 题型 + 题干/设问 + 选项/参考答案
      └─ .cq-pane__segment--note       判定结果 + 正确答案 + 解析
```

- 选择题：题号两位数字（01/02）、题型徽章、选项按钮、判定条、解析。
- 综合题：设问有序列表、「查看/收起参考答案」按钮，参考答案在题目区展开，解析落在说明区。
- 交互通过 `data-cq-*` 属性表达，事件由运行时统一委托绑定。
- 样式全部 `cq-*` / `cq-btn*`，不引用单课 `btn` / `panel` 类名（`card.css` 注释也明确这一点）。

### 3.4 卡片样式（`card.css`）

- 双栏 `grid-template-columns: 41fr / 59fr`；无材料 `is-single` 单栏；空材料保底 `has-empty-material`（0.6fr / 1.4fr）。
- `≤1024px` 双栏改上下堆叠；`≤900px` 进一步压缩。
- 分栏 `cq-cols` 使用 flex，`≤720px` 改纵向堆叠；图片 `max-width:100%`。
- 大量尺寸/颜色走 `--pw-*` 令牌，但仍存在硬编码色值（见 §8 问题 3）。

## 4. 运行时层：展示

### 4.1 对外接口

| 接口 | 位置 | 用途 |
| --- | --- | --- |
| `createPracticeView(options)` | [practiceWindow.ts](../runtime/src/practiceWindow.ts#L115-L493) | 只创建视图，外层容器由调用方负责 |
| `openPracticeWindow(options)` | [practiceWindow.ts](../runtime/src/practiceWindow.ts#L507-L674) | 开箱即用：浮层 / 页内挂载 / 嵌入画布 |
| `validateQuizData(raw)` | [validate.ts](../runtime/src/validate.ts#L60-L95) | 课后练习（sections）校验 |
| `validateModulePractice(raw)` | [validate.ts](../runtime/src/validate.ts#L125-L152) | 模块随堂练习（groups/questions）校验 |
| `createPreviewStage(options)` | [previewStage.ts](../runtime/src/previewStage.ts#L38-L97) | 1920×1080 预览画布 |
| `renderQuestionCard(options)` | [renderCard.ts](../content/renderCard.ts#L253-L258) | 单题卡片 HTML |

### 4.2 三种展示形态

| `display` | 容器 | 行为 | 使用方 |
| --- | --- | --- | --- |
| `overlay`（缺省，无 container） | `document.body` | 固定定位铺满视口、强毛玻璃遮罩、锁滚动、Esc/关闭退出 | 课程 M1–M9 随堂练习 |
| `inline`（传 container） | 指定容器 | 页内挂载，不锁滚动，提供「全屏」按钮 | 课程 M10 课后练习 |
| `embedded`（传 container） | 指定容器 | 窗口骨架铺满画布，不锁滚动、不标 `aria-modal` | 编辑器整窗预览 |

`overlay` 与 `embedded` 默认走**逐题模式 + 自动计时**；`inline` 默认列表模式、不显示计时（可显式覆盖）。同一时刻只允许一个窗口，重复打开会自动关闭上一个。

### 4.3 窗口与布局

- 浮层是 16:9 居中大窗口：`width: min(1920px, 100%, calc(92vh * 16 / 9))`，内部 `.pw-stage` 固定 1920×1080，再按容器尺寸等比缩放（`--pw-scale`，`ResizeObserver` 驱动）。
- 逐题模式：一屏一题，左材料 / 右上题目 / 右下说明；无材料时保留窄左栏并提示「本题无阅读材料」。
- 列表模式：题号点阵 + 滚动定位「当前题」；题数 ≤1 不显示进度。
- 计时：`timer:true` 正计时；`limitSeconds` 倒计时但不锁定、不阻断；`reset()` 只清作答、不清计时。
- 窄屏：`≤1024px` 窗口贴满视口并上下堆叠；`≤720px` 进一步压缩。
- 容错：数据缺失/损坏 → 空态；渲染异常 → `try/catch` 回退空态，不白屏。

### 4.4 校验规则

| 题型 | 必填/有效性 | 非法处理 |
| --- | --- | --- |
| 选择题 | 题干 + ≥2 个有 key 的选项 + 答案键必须落在选项内 | 丢弃并记录 issue |
| 综合题 | 设问或参考答案至少一个 | 丢弃并记录 issue |
| 模块 | `kind:'drag'` 原样保留占位 | 不校验内容 |
| 题组 | 逐组过滤非法题，只保留有有效题的组 | 全部无效视为缺失 |
| 版本 | `version > 3` | 仅提示，不阻断 |

### 4.5 主题机制

- 组件内视觉全部消费 `--pw-*` 令牌。
- 公共层自带 [default-tokens.css](../runtime/styles/default-tokens.css)，用 `:where(.pw, .pw-overlay)` 把优先级降到 0，保证课程配色表无论加载先后都能覆盖。
- 每课一份 `src/styles/quiz-theme.css`，写最终色值，不引用课程其它变量；构建时复制到 `dist/题目编辑器/assets/quiz-theme.css` 供编辑器读取。
- `npm run check` 校验 22 个必需令牌是否齐全，缺项报错。

### 4.6 课程侧接入

| 课程文件 | 职责 |
| --- | --- |
| [practiceStore.ts](../../../lessons/geo01-earth-universe/src/modules/practiceStore.ts) | 动态注入 `../题目编辑器/practice-data.js`，读取 `window.__PRACTICE_DATA__`；缺失回退源码内置题库 |

## 5. 编辑器层：编辑

### 5.1 形态与配置

- 源码：`editor/src/`（ESM + IIFE），由 `vite.editor.config.ts` + `vite-plugin-singlefile` 构建为**可双击的离线单文件**。
- 全部业务文案、文件名、全局变量名、结构抽取选择器都在 `DEFAULT_CONFIG` 中，可被 `window.__CONTENT_EDITOR_CONFIG__` 覆盖（[main.js](../editor/src/main.js#L36-L224)）。
- 三栏布局：左侧分组导航、中间编辑区、右侧实时预览 + 输出源码。

### 5.2 编辑模型

```text
分组（模块 / 课后练习）
└─ 题组（material + questions[]）
   ├─ 选择题：题干（纯文本）→ 选项（key+text）→ 选定项（单选）→ 解析（富文本）
   └─ 综合题：设问（每行一条）→ 参考答案（富文本）→ 解析（富文本）
```

- 题组支持折叠、上移/下移、复制、删除；题目同样支持增删改排序。
- 折叠状态用编辑器内部稳定键 `_k` 记录，导出时剔除，不进入题库。
- 旧数据迁移：`toGroups()` 把「连续且材料相同」的扁平题收敛为题组，保证不丢内容。
- 选择题固定单选；`mode` / `source` / `knowledge` / `criteria` 控件已删除。

### 5.3 富文本块编辑器（`richField.js`）

- 内核：SunEditor 3.3.3（MIT），随构建内联，离线可用。
- 块模型：一个字段 = 文本块（1 个 SunEditor）或分栏块（2/3 个 SunEditor 并排）。
- 工具栏：撤销/重做、加粗/下划线/斜体/删除线、字色/底色、项目符号、表格、图片、清除格式、源码视图。
- 图片：无上传地址 → base64 内联；默认宽 300px；渲染端 `max-width:100%` 兜底。
- 序列化：按 DOM 顺序取 HTML → 空块跳过 → 分栏包成 `cq-cols/cq-col` → 每段过 `sanitizeHtml` → 拼接。
- 反序列化：只认顶层 `cq-cols` 拆分为分栏块，其余归入文本块。

### 5.4 草稿、导入、导出、保存

| 能力 | 实现 |
| --- | --- |
| 草稿 | `localStorage`，按课程隔离，输入后 300ms 防抖保存 |
| 折叠状态 | `localStorage`，按课程隔离，以 `_k` 为索引 |
| 结构清单 | 优先载入 `assets/lesson-manifest.js`（`__LESSON_MANIFEST__`）；缺失时允许导入课程 `index.html` 现场抽取 |
| 数据导入 | 读取 `.js/.json`，正则截取 `{...}` 后 `JSON.parse`，再 `adopt()` + `normalizeState()` |
| 载入同级题库 | 动态注入 `practice-data.js`，读取全局变量 |
| 导出 | 生成 `window.__PRACTICE_DATA__ = {...}` 文本，可下载 / 复制 |
| 保存到同级文件 | File System Access API + IndexedDB 记住文件句柄；不支持时回退下载 |
| 覆盖保护 | 保存前对比同级题库，草稿缺少模块时弹窗确认；启动时提供「补齐缺失模块」 |
| 校验 | 题级字段校验 + 定位高亮；顶部状态条 + 问题徽标 |

### 5.5 实时预览

- 使用 `createPreviewStage` 建 1920×1080 画布，再以 `display:'embedded'` 调用 `openPracticeWindow`。
- 只预览当前选中的分组或课后练习，不渲染整本题库。
- 模块分组：计时 + 关闭 + 底部重做；课后练习：无计时、无关闭、无底部重做（与真实调用形态一致）。
- 缩放档位：适应宽度 / 50% / 100%。
- 预览与真实课程共用同一套卡片、窗口、样式，不存在第二套渲染。

## 6. 构建、分发与校验链路

```text
编辑题库                          构建                              分发
─────────                        ─────                            ─────
practice-data.js  ──┐
                    ├─ npm run build:editor ──▶ build/index.html
editor/src/*  ──────┘                              │
                                                   ▼
                    scripts/build.mjs ──▶ dist/题目编辑器/
                                           ├─ 题目编辑器.html
                                           ├─ practice-data.js
                                           └─ assets/
                                              ├─ lesson-manifest.js
                                              └─ quiz-theme.css
课程 index.html ──▶ 动态 <script src="../题目编辑器/practice-data.js">
```

| 环节 | 位置 | 说明 |
| --- | --- | --- |
| 编辑器构建 | `vite.editor.config.ts` | 单文件、内联全部资源、`assetsInlineLimit` 放大到 16MB |
| 课程构建 | `vite.config.ts` + `vite-plugin-singlefile` | 课程页面单文件内联；大资源外置 |
| 编辑器复制 | `scripts/build.mjs` | 复制编辑器、题库、结构清单、配色表到 `dist/题目编辑器/` |
| 开发期模拟 | `vite.config.ts` 中间件 | `/题目编辑器/*` 映射到 shared 编辑器与当前课程文件，路径与分发后一致 |
| 结构校验 | `scripts/check.mjs` | 使用共享运行时必须有 `quiz-theme.css`，且 22 个令牌齐全；远程 URL 仅告警 |
| 分发 | `scripts/build.mjs` | 构建后打包 zip（课程 + 题目编辑器） |

离线约束是整条链路的出发点：`file://` 下 `fetch` 会被 CORS 拦截，所以题库用经典 `<script src>` 注入全局变量；字体、纹理等必须 base64 内联。

## 8. 发现的问题与风险

按优先级排序：

| # | 问题 | 证据 | 影响 | 建议 |
| --- | --- | --- | --- | --- |
| 1 | **数据版本双轨**：契约 v3、geo01 数据 v2、题组使用数 0 | [validate.ts](../runtime/src/validate.ts#L14-L15)；geo01 数据实测 `version:2, groups:0` | 编辑器载入即把扁平题迁移为题组，保存/导出即写出 v3；消费方长期兼容两套结构 | 二选一收口：要么把数据迁移到 v3 并停止双写，要么明确 v2 为唯一格式、移除 `groups` 导出 |
| 2 | **导出双写导致材料重复** | `generated()` 同时写 `groups` 与扁平化 `questions`，并把组材料复制进每题（[main.js](../editor/src/main.js#L1302-L1313)） | 文件体积随题组规模增长；同一材料多份副本，改一处不同步 | 明确单一结构；若保留兼容，扁平化只作为运行时派生，不落盘 |
| 3 | **公共层自包含被局部破坏** | 空态使用 `<div class="cq-empty panel">`（[practiceWindow.ts](../runtime/src/practiceWindow.ts#L281-L286)），`panel` 是单课类名 | 编辑器预览没有单课 `.panel` 样式，空态外观与课程不一致；新课程可能样式塌陷 | 改为 `cq-empty` 自带样式，移除 `panel` |
| 4 | **主题令牌化不彻底** | `card.css` 36 处 hex + 9 处 rgb/rgba；`practiceWindow.css` 17 处 hex + 1 处 rgb/rgba（如 `.cq-pane__label` 渐变 `#1d71b5 → #16558f`） | 换课只改令牌无法完全换肤；与设计文档「组件内不写死颜色」冲突 | 把剩余色值收进令牌；`check.mjs` 增加 CSS 字面量检查 |
| 5 | **文档与实现漂移** | 旧文档仍写 Markdown、`custom-quiz.js`、「零依赖单文件」；窗口尺寸文档写 ~1560×900，实际为 16:9 最大 1920 | 新成员/新课程按旧文档接入会踩坑 | 在旧文档顶部标注「已过时」，以本报告与现行源码为准 |
| 6 | **编辑器缺少自动化测试** | `main.js` 2025 行无对应测试 | 结构迁移、导入导出、覆盖保护等回归只能靠人工 | 优先给纯函数补测：`toGroups` / `normalizeState` / `generated` / `collectIssues` |
| 7 | **属性转义不完整（低风险）** | `escapeHtml` 只转义 `& < >`，不转义引号（[richText.ts](../content/richText.ts#L19-L21)）；`renderCard` 用它拼接 `data-key` 等属性 | 教师手工写入含引号的选项 key 时可能破坏属性结构 | 属性统一走 `attr()`（转义引号），或在校验层限制 key 为单个字母 |
| 8 | **题库无引用机制** | 题目物理内联在各模块/题组；`id` 可选且只用于 UI 状态 | 同一道题不能跨练习复用；改原材料不会同步 | 若确有需求，另立「材料表 + 题目表 + id 引用」课题，不在现有 schema 上打补丁 |
| 9 | **编辑器体积较大** | 单文件 1.14MB（SunEditor 内联） | 首次打开略慢；离线分发可接受 | 保持现状即可；若需优化，可评估按需加载或裁剪 SunEditor 插件 |

补充说明：

- `validateQuizData` 只接受 `sections`，题组形态的 `CqData` 需要走 `validateModulePractice`；这是有意分层，不是缺陷，但接入方容易误用。
- 拖拽题（`kind:'drag'`）明确不在公共层范围内，由课程页面自行实现；编辑器中只读占位。
- 多选题仅保留遗留数据兼容分支，编辑器不产出；`answer` 数组不应再作为新数据写入。

## 9. 结论与建议

### 9.1 已经做对的部分

1. **单一真源**：卡片、清洗、校验、类型各只有一份，课程侧不复制代码。
2. **展示与编辑共用渲染**：编辑器预览直接调用运行时，不存在「预览一套、课程一套」的漂移。
3. **离线优先**：题库用经典脚本、编辑器单文件、资源内联，符合 `file://` 分发约束。
4. **主题与结构分离**：课程只提供配色表与题库，公共层不依赖单课类名（除空态一处）。
5. **容错完整**：数据缺失、损坏、渲染异常都有空态兜底，不白屏。
6. **工程门槛**：类型检查、109 项测试、结构校验全部通过。

### 9.2 建议的处理顺序

| 优先级 | 事项 | 理由 |
| --- | --- | --- |
| P0 | 收口数据版本（v2 或 v3 只保留一种落盘格式） | 这是当前唯一会让教师「保存一次就改变结构」的问题 |
| P0 | 去掉空态对单课 `.panel` 的依赖 | 一行改动，直接修复预览/新课程不一致 |
| P1 | 清理公共层硬编码色值并纳入校验 | 保证「换课只改令牌」的承诺成立 |
| P1 | 给编辑器纯函数补最小测试 | 结构迁移与导出是高风险区，且容易测 |
| P2 | 统一/标注过时文档 | 降低后续接入成本 |
| P2 | 评估是否需要跨题/跨练习复用 | 若需要，属于新课题，不应在现有扁平结构上叠加隐式引用 |

### 9.3 不建议做的事

- 不建议为了「复用」在现有 `questions` 里加隐式引用字段而不改数据层——会让校验、编辑器、运行时三处同时复杂化。
- 不建议恢复 Markdown 兼容层——设计已明确只存 HTML，双语义会重新引入漂移。
- 不建议把编辑器改成框架工程——当前单文件离线形态是分发约束下的合理选择。
