## 2. 已明确内容
- 教学目标：知识（宇宙概念、天体类型与判别、天体系统层级、八大行星与三性、地球存在生命条件）+ 能力（分类归纳、判别应用、空间想象）+ 素养（区域认知、综合思维、地理实践力、探索兴趣）。能力与素养目标已由教学设计专家补充（原输入为"自行补充"）。
- 核心知识点：10 条（宇宙、天体、7 类常见天体、天体类型、判别三条件、天体系统概念、层级、八大行星、分类与三性、生命条件）。
- 关键互动：天体卡片档案（点击展开）、流星案例分步、天体/非天体拖拽分类（触屏降级为点击）、天体系统层级逐级放大、3D 太阳系（点击行星出信息卡）、地球生命条件因果链分步点亮、复习模式、每模块"⊕ 拓展"浮层。
- 页面结构方向：混合型单页长页面，深空宇宙感视觉，模块 M0~M10 顺序 = 教学流程 S1~S6 展开顺序。
- 技术路线方向：原生 HTML/CSS/JS 为主，仅 M6 引入 Three.js（本地化离线）；SVG 承担层级图与因果链；数据集中到 `lessonData` 对象便于教师维护。

## 3. 待决策项
1. 课时与时长：原输入未填写（模板示例文字残留），已默认"1 课时 / 40 分钟"，需用户确认。
2. 3D 太阳系 vs 2D 示意图：用户要求"采用现有的包展示"，同时"必须离线可用"。Three.js 本地化可满足离线，但增加约 600KB 体积且对老设备不友好。推荐：默认做 3D（本地库），内置 WebGL 检测自动降级为 2D SVG 轨道图。是否接受该方案请用户确认。
3. 天体系统层级的"同级别案例"范围：用户希望"同一级别再列出其他行星系"（如火星的卫星系统、其他恒星系）。已放入 M5 拓展浮层与层级节点案例文本中。若用户希望做成独立交互模块（而非浮层补充），会增加 P2 级开发量，暂缓。
4. 能力/素养目标措辞：教学设计专家已补充（见 01 文档第 3 节），请用户确认是否符合预期。
5. 复习模块形态：用户要求"有单独的复习模块设计"。已设计为 M9"复习与总结"（结构图 + 复习模式切换）。复习模式为隐藏讲解、仅留结构与练习，是否满足预期请确认。

## 4. 范围控制建议
- 本轮只做：M0~M10 全部模块的 P0/P1 功能（详见 05 开发文档优先级分层），资源全部本地化，离线可运行，桌面投屏优先。
- 暂缓内容：例题模块（预留入口占位）、真实图片素材（占位）、统计图表、P2 增强项（3D 天体系统多级模型、行星严格比例建模）。
- MVP 建议：先交付"无 3D"版本（M6 用 2D SVG 轨道图）跑通全流程，3D 作为第二阶段增强接入。若开发时间紧张，此 MVP 已可完整支撑 40 分钟课堂。

## 6. 冲突与风险（本阶段交叉检查结论）
- 冲突点 1：用户"采用现成的包展示八大行星/天体系统" ↔ "必须离线可用"。决策：采用 Three.js 本地化（下载至本地 libs 目录，不引 CDN），程序化生成球体与轨道，无需联网纹理；WebGL 不可用时自动降级 2D。理由：Three.js 是成熟轻量的 3D 方案，本地单文件即可离线。
- 冲突点 2：知识点量大（10 条）↔ 40 分钟课时。决策：宇宙起源、行星际物质等非核心细节归入"拓展浮层"或一句话带过；课堂主线只讲重点与易错点。理由：教学目标优先，避免认知负荷过载。
- 冲突点 3：学生"基础较差、注意力不集中" ↔ 知识密度高。决策：信息分步呈现（卡片展开、分步点亮、逐级放大），互动穿插节奏（S5 拖拽练习），投屏大字。理由：页面节奏服务课堂节奏。
- 风险点：3D 在投影设备不可用的概率不低，降级方案必须可用；拖拽在触屏大屏失效，降级为点击选择已纳入实现范围。
- 是否建议降级或删减：是。P2 项（3D 多级天体系统模型、行星严格比例）本轮不实现；例题与图片仅占位。
