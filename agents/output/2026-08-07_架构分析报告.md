# 教学互动网页开发项目 · 架构分析报告

> 迁移说明（2026-08-07）：`prompts/`、`templates/`、根目录 `current_task.md`、`output/` 已集中到 `agents/` 目录（即 `agents/prompts/`、`agents/templates/`、`agents/current_task.md`、`agents/output/`）。报告中路径均指迁移前状态。`scripts/` 为工程脚本目录。

- 日期：2026-08-07
- 范围：教学网页设计项目的整体架构（Vite 构建、课程工程、资源管理、打包分发、部署、Agent 体系）
- 性质：基于项目实际代码与配置的系统性分析，供后续决策与改造使用

## 0. 结论摘要

架构骨架（单课工程 + lesson.json 元数据 + 交接模板）方向正确，当前主要矛盾有三组脱节：

1. **配置硬编码单课** 与 **多课规模开发**：`vite.config.ts` 的 `root`、`@` alias 写死为"地球的宇宙环境"，每新增一课都要手改配置。
2. **"单 HTML 分发"假设** 与 **重资源（视频 / 3D）**：单文件内联仅对轻量课成立，视频与 3D 模型只能以独立文件输出，分发策略需区分。
3. **Agent 角色定义** 与 **实际职责边界**：总控提示词中提及"代码生成 agent、质检 agent"，与"agent 只负责生成开发报告"的既定边界不符。

### 既定约束（本次分析的前提）

- **资源本地化**：本项目不实现在线文件；无需"断网自动降级"机制。所有资源文件默认保存在本地、直接调用。
- **不建 workflows/ 目录**：Agent 工作流由项目外的其他 Agent 应用操作，不在项目本地编排（避免本地脚本调用 AI API）。
- **Agent 职责边界**：Agent 只负责生成开发报告（教学设计 / 页面设计 / 技术实现 / 总控 / 开发文档），不负责代码实现；代码由 AI 编程工具按开发文档执行。

## 2. 不匹配点与潜在问题

### 2.1 构建配置：单课硬编码（最高优先级问题）

- `vite.config.ts` 中 `root`、`base`、`@` alias 全部写死为"地球的宇宙环境"。**每新增一课都要手改配置文件**，且同一时刻只能开发/构建一课。
- 构建注释中"可扩展脚本循环 `vite build --root <课>`"的设想**尚未落地**，多课构建无任何承载方式。

### 2.2 资源管理缺陷

- **违反本地化约束**：`index.html` 等 8 处图片使用远程 URL（trae-api），与"所有资源保存在本地、直接调用"的既定约束直接冲突。
- **无资源清单**：`lesson.json` 未登记 `resources` 字段，无法校验资源完整性、无法生成分发清单、无法控制单课体积。
- **无资源约定**：`assets/` 无子目录分类（images/videos/models）、无命名规范、无体积阈值。

### 2.3 单文件打包与重资源冲突

- `vite-plugin-singlefile` 会把 JS/CSS 及内联资源打进一个 HTML；本地图片会被 base64 内联（体积膨胀约 33%），**视频/3D 模型（GLB）无法内联**，只能以独立文件输出。
- 即"单 HTML 分发"仅对轻量课成立；一旦出现视频/3D，dist 就变成 `index.html + assets/*` 的**多文件目录**，而当前 README/lesson.json 的措辞仍假设"只需拷贝一个 HTML"。分发策略存在事实与文档脱节。
- `three@0.180` 被全量打入单文件（约 600KB+），课堂低配设备首次加载慢；`solar.ts` 已有 WebGL 降级，但体积问题仍在。

### 2.4 构建流程缺陷

- **无多课构建机制**：`npm run build` 只构建硬编码一课；无法批量构建、无法增量构建。
- **typecheck 全局耦合**：`tsconfig.json` 的 `include` 覆盖全部 `lessons/**/src`——**任一课的 TS 错误会阻塞整个项目的 typecheck/test**，多课开发时互相踩踏。
- **无结构校验**：没有机制检查"lesson.json status=done 但 dist 不存在""entry 指向的文件缺失"等问题。

### 2.5 系统整合（成书）能力不足

- `books/必修一/book.json` 中的课程列表与各课 `lesson.json` **元数据重复维护**（标题/章节/顺序/入口），且 README 声称"自动汇总"但无任何生成机制；也无整书首页/导航页生成器。

### 2.6 部署策略缺位

- 无部署配置/脚本；`dist/` 被 `.gitignore` 忽略，产物只能本地构建后手动上传，难以支撑"部分课程整合上线 + 后续完整上线"。

### 2.7 中文目录名的分发风险

- `lessons/地球的宇宙环境/`、book.json 内 `path` 均含中文。本地 file:// 与 Windows 无碍，但**静态托管/CDN/部分打包工具对中文路径存在编码风险**。**决策：存量课一并迁移**为 ASCII 课程序号目录，中文标题存入 lesson.json。（已于 2026-08-07 完成迁移：`lessons/geo01-earth-universe/`）

## 4. Agent 边界与集中管理评估

### 4.1 职责边界确认

- **Agent 只产出开发报告**：依次输出 教学设计交接包 → 页面设计交接包 → 技术实现交接包 → 总控摘要 → 开发文档，终止于文档交付。
- **代码实现由 AI 编程工具完成**：按开发文档（docs/05_开发文档.md）执行，即 AGENTS.md 推荐工作流第 7 步。
- **现有冲突点**：`总控agent.md` 中提到"代码生成 agent、质检 agent"两类角色，与上述边界不符，需修订提示词使之一致（或明确这两类角色不在本体系内）。

### 4.2 集中管理的可行性与挑战

**可行性高**：`prompts/` 集中存放 + 交接模板 + docs/01~05 编号已构成良好骨架。挑战如下：

1. **角色定义不一致**：提示词中残留"代码生成/质检"角色描述，与"只出报告"边界冲突。
2. **提示词版本漂移**：提示词无版本号/变更记录，迭代后无法追溯"某课是用哪个版本生成的"。
3. **交接质量无校验**：无机制验证每课 docs/ 是否齐备 01~05、交接格式是否符合模板（跨 Agent 信息丢失风险）。
4. **编排在项目外**：多 Agent 的执行与编排由项目外 Agent 应用承担，项目本地不保留任何 Agent 编排脚本。

## 5. 优化建议

> 说明：所有"工程脚本"均为纯构建/校验/打包操作，**不调用任何 AI API**；Agent 编排与文档生成一律在项目外进行。为避免在根目录新增 `workflows/` 目录，工程脚本统一收敛到 `package.json` 的 npm scripts（必要时配少量 `scripts/` 目录下的纯 Node 脚本）。

### A. 项目结构

1. **lesson.json 升级为单课唯一真源**：新增 `resources`（path/type/size）、`bundle`（`single` | `multi` 构建模式）；`engine` 字段已存在。book.json 只保留汇总结果，不再手写。
2. **课程目录统一使用 ASCII 编号**（如 `lessons/geo01-earth-universe/`），中文标题存入 lesson.json；**存量课同步迁移**（当前课 → `geo01-earth-universe`），迁移时同步更新 `lesson.json`、`books/必修一/book.json`、`vite.config.ts` 与 docs/ 中的引用路径。

### B. 构建配置（不新增 workflows/ 目录）

3. **vite.config.ts 参数化**：`root` 从环境变量/CLI 读取（如 `vite build --root lessons/<课>`），`@` alias 随之动态解析；未指定时回退到默认课。
4. **多课构建用 npm scripts 承载**（纯工程操作，无 AI API）：
   - `build:all`：遍历 `lessons/*/lesson.json`，对每个 bundle 模式依次构建（单条 Node 脚本即可，置于 `scripts/build.mjs`）；
   - `build:lesson:<课>` / 参数化 `build -- --lesson=<课>`：按课单独构建；
   - `check`：结构校验（status=done 必须有 dist/entry、resources 引用齐全、docs 01~05 齐备、无远程资源残留）。
5. **双构建模式（首期实现，决策 2026-08-07）**：
   - 轻量课（无视频/3D）：维持 `vite-plugin-singlefile` 单 HTML；
   - 重资源课：关闭 singlefile，输出 `index.html + assets/`（Vite 自动加内容哈希），再打包 zip。
   - 由 `lesson.json.bundle` 驱动构建脚本按课选择配置。
6. **typecheck 解耦**：新增按课检查（`tsc --noEmit` 配合分课 tsconfig 或临时 include），根级 build 不被单课错误阻塞；保留全量检查作为发布前门禁。
7. **大包拆分**：多课共用 three 时，重资源课可对 three 做 `manualChunks`，首屏更快。

### C. 资源管理（严格执行本地化）

8. **远程图片落地**：将当前课 8 处远程图片下载进 `assets/images/`（构建时内联，直接本地调用）；**确立规则：单课 HTML/CSS/JS 一律引用本地资源，禁止远程 URL**；`check` 脚本对"远程资源残留"采用**宽松（告警）**拦截，不阻塞构建（决策 2026-08-07）。
9. **规范 assets 目录**：`assets/{images,videos,models,audio}/`，snake_case 命名，全部登记进 `lesson.json.resources`；由 `check` 脚本校验引用一致性。
10. **体积阈值**：单课 dist 超阈值（如 50MB，以视频/模型为主）时构建告警；GLB 建议 Draco 压缩，视频建议转 H.264。
11. **shared/ 复用方式**：由构建期脚本（scripts/copy-shared.mjs，纯文件拷贝）统一拷贝进单课，替代人工复制，避免样式漂移；单文件课仍可内联。

### D. 部署策略

12. **整书可部署物**：`npm run build:all` 全量构建 → 汇总到 `dist-book/`（各课子目录 + 生成的整书首页），`base:'./'` 已保证子路径可访问，直接上传任意静态托管；增量上线时只重新构建/上传改动课。
13. **books 自动汇总**：`npm run assemble` 扫描各课 lesson.json，自动重建 `books/*/book.json` 并生成整书首页/章节目录/上下课导航（纯 Node 脚本，无 AI API）。
14. **CI 门禁（可选）**：GitHub Actions：typecheck → test → check → build:all → 部署到静态托管，使 dist 被 .gitignore 也不影响可追溯性。

### E. Agent 治理（支持持续迭代，编排在项目外）

15. **收敛角色定义**：修订 `总控agent.md`，删除"代码生成 agent、质检 agent"残留描述，明确本体系 Agent 输出终止于开发文档；代码实现由 AI 编程工具执行。
16. **提示词版本化**：`prompts/` 文件头加 `version` 字段 + 变更记录约定；根目录 AGENTS.md 增加"Agent 注册表"（角色/职责/输入输出路径/边界），作为集中管理的唯一权威清单。
17. **任务输入按课归档**：保留 `lessons/<课>/docs/current_task.md`（已有），根目录 current_task.md 仅作活动任务指针。
18. **交接机器可读化（可选）**：在 templates/ 补充手写交接模板对应的 JSON schema，供项目外 Agent 应用直接消费，为自动化交接打基础。
